# План: достроить сайт по ТЗ до запуска (этапы 4 → 5 → 3 → 6 → 7 → 8)

Решение владельца 2026-09-26: строим всё по ТЗ без остановок, чтобы появилась готовая база; правки владельца — **после** прогона до Этапа 8,
тогда же выбираем домен и хостинг. План одобряется один раз, дальше — маленькие шаги (тесты + коммит после каждого), итог каждого этапа
показываю владельцу. Неясное — беру из прототипа/ТЗ, помечаю «допущение» и пишу в `docs/QUESTIONS-TO-OWNER.md` (не останавливаюсь).

Опора: в базе (Этап 0) уже заложены таблицы клиентов, склада, упаковок, оптовых цен, совместимости, промокодов, партнёров, баннеров,
шаблонов, журнала действий — большую часть схемы не придумываем, а оживляем.

## Этап 4 — Админка (заказы, клиенты, склад, отчёты)
| Шаг | Что |
|---|---|
| 4.1 | **Клиенты**: список (поиск по телефону/имени), карточка — заказы, сумма покупок, уровень, заметка, личная скидка, язык; журнал изменений контактов |
| 4.2 | **Шаблоны сообщений** по статусам (укр/рус, `{name} {no} {ttn} {sum}`), при смене статуса менеджер отмечает, какие отправить, + свой текст; флаг «автоматически». Доставка покупателю — через бота (Этап 5), до того — «не отправлено» + кнопка «скопировать текст» |
| 4.3 | **Заказы+**: фильтры (канал, источник, даты, оплата, доставка), новые статусы в интерфейсе с причинами отмены, создание заказа менеджером (звонок), тестовые заказы, печать счёта/накладной/комплектовочного листа |
| 4.4 | **Склад**: резерв при заказе → списание при «Отправлен» → возврат при отмене; документ «Приход»; инвентаризация (факт → разница в журнал); журнал движений; минимальный остаток и «заканчиваются»; закупочная цена |
| 4.5 | **Инструменты владельца**: прибыль по заказу (продажа − закупка − скидка − комиссия − доставка), постоянные расходы → прибыль за месяц; правила наценки по разделам/сериям и округление до «…9 ₴»; минимальная маржа; возвраты и гарантийные обращения с причинами; задачи-напоминания в заказе/клиенте |
| 4.6 | **Отчёты (базовые)**: главный экран (выручка, прибыль, заказы, средний чек, новые/повторные клиенты, сравнение с прошлым периодом, «требуют действия», «заканчиваются»), продажи, товары (топ, без продаж 30/60/90), заказы (скорость обработки, отмены по причинам), статистика каталога; выгрузка в Excel (CSV); деньги и маржу видит только владелец (новое право); тестовые не считаются |
| 4.7 | **Безопасность**: вход с кодом из приложения (Google Authenticator), журнал действий в админке, «выйти со всех устройств» для сотрудника, приглашение сотрудника |
| 4.8 | **Уведомления**: фоновые задачи (Redis), сводка владельцу в 21:00, отчёт в понедельник, тревоги (импорт не прошёл, хит закончился, мало на складе); админка удобна с телефона + значок «установить как приложение» |

## Этап 5 — Бот, Mini App, единый клиент, кабинет
| Шаг | Что |
|---|---|
| 5.1 | **Бот (grammY)**: /start, язык, кнопка «Магазин» (Mini App), «поделиться номером» → привязка к клиенту, сообщения о заказе по шаблонам, уведомления менеджерам (перенос из Outbox) |
| 5.2 | **Mini App**: тот же сайт в Telegram — вход автоматически по данным Telegram, кнопки Telegram (назад, главная кнопка), тактильная отдача |
| 5.3 | **Вход на сайт**: через Telegram и по SMS-коду (провайдер — заглушка до ключа); один клиент по телефону, объединение истории |
| 5.4 | **Уровни скидок** Старт/Майстер/Профі/Легенда + личная скидка, расчёт на сервере, настройки в админке (пороги, %, вкл/выкл); реферальная ссылка и учёт приглашённых |
| 5.5 | **Кабинет**: заказы со статусом и ТТН, повтор заказа, уровень и прогресс, избранное, «Мой инструмент», общая корзина сайт ↔ Mini App |
| 5.6 | **Витрина+** (из ТЗ, не вошло в Этап 2): совместимость «Підходить до», фильтр «к моему инструменту»; цена за упаковку и опт от N шт; отзывы с фото и вопросы (модерация в админке); «Повідомити про зниження ціни / надходження» через бота; сравнение; «Передзвоніть мені» |

## Этап 3 — Оплата и доставка (всё на заглушках до ключей)
| Шаг | Что |
|---|---|
| 3.1 | Раздел **«Интеграции»**: ключи в базе зашифрованы, показываются маской, только владелец, кнопка «Проверить подключение», без ключа — заглушка |
| 3.2 | **mono**: счёт на предоплату/полную сумму, автоматически «Оплачен» по уведомлению mono, страница «ждём оплату», возврат; «частинами» mono/Приват — заглушка до договоров |
| 3.3 | **Checkbox**: чек после оплаты, ссылка клиенту в бот/почту |
| 3.4 | **Нова Пошта**: ТТН кнопкой, печать наклейки, автостатусы → «Получен» + сообщение клиенту, стоимость и срок в корзине/карточке, бесплатная доставка от суммы, отчёт по отказам, чёрный список (только предоплата) |
| 3.5 | Счёт PDF (печать) для ФОП/компаний; **KeyCRM** (как в прототипе, выключен по умолчанию) |

## Этап 8 — Подготовка к запуску (то, что можно без домена)
Ежедневные бэкапы с проверкой восстановления, журнал ошибок, защита от спам-заказов, сборка для сервера (Docker), инструкция переезда,
чек-лист тестовых заказов и браузеров (iPhone, Android, Telegram, Instagram, TikTok). Затем — **правки владельца**, выбор домена и хостинга,
настоящие ключи, открытие для Google.

## Отложено на после запуска
IP-телефония, мониторинг цен конкурентов, ИИ-помощник подбора, единое окно сообщений (Instagram/Viber), Укрпошта, выгрузка на Prom/Rozetka,
план продаж менеджеров, закупки с автозаявкой поставщику.

## Допущения (в `docs/QUESTIONS-TO-OWNER.md`, владелец может поменять потом)
1. Уровни скидок — пороги прототипа 5 000 / 15 000 / 40 000 ₴, 0/3/5/10 %, по умолчанию **выключены**, включаются в админке.
2. Резерв: при заказе — резерв, при «Отправлен» — списание, при отмене — возврат.
3. Реферальная программа: ссылка и учёт приглашённых; размер бонуса — настройка, по умолчанию выключено.
4. SMS-вход: провайдер не выбран → заглушка.
5. KeyCRM: делаю подключение, выключено по умолчанию.
6. Mini App и вход через Telegram на сайте полностью проверяются только с доменом (https) — на Этапе 8.
7. Генерация описаний — нужен ключ ИИ-сервиса → заглушка.
