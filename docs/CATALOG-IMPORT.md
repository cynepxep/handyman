# Каталог: импорт, ручные правки, поиск (Этап 1)

Правила, по которым каталог Vitals попадает в базу. Перенесены из старого проекта (`handyman/src/feed.js`,
`docs/04-BUSINESS-RULES.md`) и дополнены требованиями ТЗ. Код: `packages/core/src/catalog/` (чистая логика, без базы)
и `packages/db/src/catalog-*.ts` (запись в базу и поиск).

## Как это работает

1. **Проверка** (`/admin/import`): фид скачивается по ссылке (или загружается файлом), разбирается и сравнивается с базой.
   В каталог **ничего не записывается**. Файл сохраняется в `apps/web/.data/feeds/` (или `FEEDS_DIR`), хранятся последние 3.
2. Владелец смотрит числа, при необходимости меняет сопоставление категорий («Сохранить выбор и пересчитать») и
   отмечает подтверждённые скачки цен.
3. **Применить**: импорт идёт в фоне (полоса прогресса, страницу можно закрыть). Плюс поиск пересобирается автоматически.
4. Итог и журнал — на той же странице. Каждый запуск сохраняется в `ImportRun`, действие пишется в `AuditLog`.

## Фид Vitals (проверено на живом файле 2026-09-24)

`https://vitals.ua/index.php?route=extension/feed/prom` отдаёт файл программе без ограничений (~14 МБ, ~2000 товаров, ~345 категорий, 5 уровней).

| Что в фиде | Как обрабатываем |
|---|---|
| Кодировка не указана в ответе сервера | Читаем как UTF-8 (по объявлению `<?xml encoding>`, поддержаны также windows-1251 и др.) |
| Теги `<item>`: `vendorCode`, `articlCode`, `name`, `description`, `features_text`, `price`, `oldprice`, `available`, `quantity_in_stock`, `categoryId`, `url`, `picture`×N, `param name=…`×N | См. ниже |
| `vendorCode` уникален | Это наш артикул `sku`. Строка: ведущие нули важны («000237651») |
| `available` — **тег**: `true` или пустой | Пустой = нет в наличии. `quantity_in_stock` бывает только 0 или 1 — это признак, а не количество |
| Тега бренда нет | Бренд берётся из настройки поставщика «Бренд по умолчанию» (Vitals) |
| Только украинский язык | Русское название пока копия украинского; описание на русском пусто (на сайте показывается украинское) |
| `description` и `features_text` — HTML, закодированный сущностями (`&lt;p style=&amp;quot;…`) | Раскрываем, чистим (см. «Безопасность») и склеиваем: сначала особенности, потом описание |
| Служебные записи с названием «-» (9 шт., без категории и фото) | Пропускаются с замечанием «Нет осмысленного названия» |
| Товары без `categoryId` (2 настоящих) | Загружаются в системную категорию **«Нераспределённые»** (`unsorted`): покупателям и поиску не видны, владелец раскладывает их вручную (галочки + «Перенести»). Можно назначить категорию сразу или «не загружать» на экране проверки |
| Корневая категория «Архів продукції» (~352 товара) | По умолчанию не загружается (как в старом проекте) |
| «Будівельна хімія» (12) | По умолчанию не загружается: ТЗ исключает стройматериалы. **Допущение**, меняется на экране проверки |

Формат Prom/YML (`<offer>`, `available="…"` атрибутом, запятая в цене) тоже поддержан, покрыт тестом, но на реальном файле не проверялся.

## Цены

- **Цена в фиде Vitals — рекомендованная розничная цена (РРЦ)**, поэтому наценка 0% и округления нет: цена в магазине = цене фида
  (`price`), старая цена = `oldprice` (только если она выше цены). Так решил владелец («не можем отличаться от РРЦ»).
- Механизм наценки сохранён для будущих поставщиков: `Supplier.markupPct` (в процентах, к цене и к старой цене).
- `Product.supplierPrice` = цена по фиду (с наценкой, если она есть): с ней сравнивается ручная цена.
- **Закупочная цена** `Product.purchasePrice` — наша цена покупки. В фиде Vitals её нет, поэтому пока вводится вручную в карточке товара
  (способ расчёта, например «РРЦ минус наша дилерская скидка %» по поставщику/категориям, владелец ещё не выбрал). Импорт её не меняет,
  замка не требует. Видна и правится с правом «Цены»; в публичный поиск/API не попадает. Из неё считается заработок с единицы и маржа.
- Каждое изменение цены пишется в `PriceLog` (источник: `IMPORT`, `MANUAL`, `SUPPLIER`).
- **Скачок цены больше 30%** (требование ТЗ) импортом не применяется: товар попадает в список «Резкое изменение цены»,
  где владелец отмечает подтверждённые. Остальные поля такого товара обновляются, цена остаётся прежней.

## Ручные правки и защита от импорта

- Любое поле, изменённое человеком в карточке товара, автоматически защищается (`ProductFieldLock`) и импортом не перезаписывается.
  Защищаемые поля: название (укр./рус.), описание (укр./рус.), цена, старая цена, категория, видимость, бренд, поставщик.
- Защиту можно снять в карточке товара («Снять защиту»): при следующем импорте поле снова возьмётся из фида.
- Пустые значения из фида (описание, картинки, характеристики) не затирают заполненные.
- Русское название обновляется импортом, только пока оно копия украинского (то есть его ещё не переводили).
- **Расхождение цен**: цена защищена вручную и отличается от цены поставщика. Импорт цену не трогает, товар получает
  `priceConflict`. Решение: «Принять цену поставщика» (цена берётся из фида, защита снимается, запись в истории цен).
  Если ручная цена ниже РРЦ, в карточке показывается предупреждение (контроль РРЦ из ТЗ).
- Ручная правка описания очищается от опасного HTML так же, как описания из фида.

## Наличие и пропавшие товары

- Загружаются **все** товары, в том числе «нет в наличии» (решение владельца): страницы не удаляются (это важно для Google).
  Такие товары показываются как «Под заказ».
- `Product.supplierAvailable` — наличие **у поставщика**. Собственный остаток «в Одессе» появится на Этапе 4 (склад).
- Товар пропал из фида или перенесён в пропускаемую ветку (архив): остаётся на сайте, `supplierAvailable=false`,
  `missingFromFeedSince` = дата. Вернулся в фид — метка снимается. Удаление товаров импортом **не происходит**.
- Ручные товары (`source=MANUAL`) и товары других поставщиков импортом не затрагиваются.

## Категории

- Наши верхние категории: `ak`, `el`, `gr`, `hand`, `acc`, `bld`, `pw` (сид Этапа 0) плюс создаваемые из корней фида.
- **Автоподсказка** (`suggestDecision`, `categories.ts`) по названиям в порядке приоритета:
  архив → пропуск; строительная химия → пропуск; «Силова техніка» → `pw`; всё, что содержит «акумуляторн/SmartLine/M-Type» → `ak`;
  «витратні/аксесуари/оснастка» → `acc`; генераторы, компрессоры, зарядные, двигатели → `pw`; строительное оборудование → `bld`;
  «Ручний інструмент…» → `hand`; «Електроінструмент» → `el`; «Садово-паркова» → `gr`; неизвестный корень (сварка, лазерная техника,
  обогреватели, масла) → **новая** категория с его названием.
- Решения владельца хранятся в `FeedCategoryMap` (поставщик + путь ветки). Действует **самый длинный совпавший путь**: можно
  сопоставить корень, а отдельную подгруппу переопределить. «Автоматически» возвращает подсказку.
- **Подкатегории** создаются автоматически из структуры фида: под нашей категорией не больше 2 уровней (глубже сворачиваются
  в 2-й). Код: `<родитель>-<слаг названия>` (украинская транслитерация). Названия и порядок потом можно менять в «Категориях»,
  импорт их не перезапишет.
- Допущение: автоподсказка — стартовая. Проверьте результат на экране «Куда класть товары» при первом импорте.

## Безопасность

- Очистка HTML описаний (`sanitizeHtml`): остаются `p, h2–h4, ul/ol/li, b/strong, i/em, u, br, table…, a[href]`;
  все атрибуты (style, onclick…) удаляются; `script/style/iframe` вырезаются; `h1` становится `h2`; ссылки только http(s), tel, mailto.
- Ссылка на фид: только http/https, адреса локальной сети и localhost запрещены. Размер файла до 200 МБ.
- Загрузка файла: лимиты Next подняты до 60 МБ (`next.config.ts`; иначе `proxy.ts` молча обрезает тело запроса на 10 МБ).
- Все действия — под правами `import.run`, `products.edit`, `prices.edit`, `suppliers.edit` (новых прав нет).

## Поиск (Meilisearch)

- Индекс `products` — копия **видимых** товаров (скрытые убираются). Источник правды — PostgreSQL.
- Обновление: после импорта (полная пересборка, ~3 с на 1600 товаров), после правки товара (один документ), после правки категории;
  вручную — кнопка «Пересобрать поиск» на главной или `pnpm search:reindex`. Если Meilisearch недоступен, импорт и правки
  проходят, а поиск помечается «отстаёт» (`Setting: search.stale`) — на главной админки это видно.
- Опечатки допускаются в названиях, но не в артикулах. Поиск по артикулу работает и без ведущих нулей.
- **Раскладка**: если по запросу ничего нет, а он набран латиницей, пробуем переведённый вариант (`rheu` → `круг`).
- **Синонимы** (`SYNONYM_GROUPS`, `search-text.ts`): болгарка = УШМ = КШМ, шуруповёрт = шурупокрут и т.д., русские слова сведены с украинскими.
  **Допущение**: стартовый список, дополнять по запросам без результатов.
- Порядок: «в наличии» всегда выше «под заказ», внутри — по релевантности или выбранной сортировке.
- **Фильтры** (`FACET_DEFS`, `facets.ts`): в фиде ~2000 разных названий характеристик, поэтому фильтры — из проверенного списка
  (диаметр, посадка, толщина, материал, хвостовик, тип шлица, количество в упаковке, напряжение, мощность, тип двигателя, паливо,
  зернистость, призначення, тип) плюс «Серія» (из названий категорий), бренд, цена, наличие, скидка. Технические характеристики
  (габариты, вес нетто/брутто) в фильтры не попадают. Добавить фильтр: запись в `FACET_DEFS` → `pnpm search:reindex`.
- Счётчики фильтров: у выбранной группы показываются и другие значения (счётчики считаются без её собственного фильтра).

### Публичный API для витрины (Этап 2), Mini App и бота

`GET /api/catalog/search` — параметры: `q`, `cat` (категория со всеми вложенными), `brand` (повторяется), `min`, `max`, `avail=1`, `sale=1`,
`f.<код фильтра>` (повторяется), `sort` (`relevance|price_asc|price_desc|new|name`), `page`, `per` (до 60).
Ответ: `total, page, pages, items[], facets{ brand, categories, price, attrs }, correctedQuery, processingMs`.

`GET /api/catalog/suggest?q=…` — подсказки для шапки (до 6: название, фото, цена).

Ключ Meilisearch остаётся только на сервере. Ошибки: 503 с понятным сообщением, если поиск недоступен или индекс не создан.

## Известные ограничения

- Картинки — ссылки на vitals.ua (1000×1000, ~300 КБ). Свой хостинг/уменьшение — на этапе картинок. Проверить в условиях дилерства
  (ТЗ п. 9), можно ли так делать.
- Расписания автоимпорта нет (только кнопка). Появится вместе с очередями (Redis/BullMQ) на Этапе 3+.
- Печать ценников (`PriceLog.tagDone` из старого проекта) и Excel/CSV-импорт других поставщиков не перенесены.
- Русских названий и описаний нет (фид Vitals только на украинском).
- Архивные товары Vitals не загружаются вовсе. Если понадобятся (например, для старых заказов), выберите для ветки «Архів продукції» любую категорию.
- Список товаров в админке использует PostgreSQL (`ILIKE`), а не Meilisearch: всегда актуален, быстро для тысяч позиций.
  При росте каталога до десятков тысяч перевести на Meilisearch.
