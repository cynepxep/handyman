**Рекомендация (допущение — зависит от вашего бюджета и наличия дизайнера):** если дизайнера нет и бюджет ограничен — **вариант 3 или 2**; если есть дизайнер или вы хотите профессиональный бренд — **вариант 1**. Решение принимаете вы.

## Порядок согласования (любой вариант)

1. **Бриф и материалы** (`01`, `06`): вы отвечаете на вопросы, собираем материалы.
2. **Направление и дизайн-система**: цвета, шрифт, кнопки, поля, карточка товара — **согласование владельцем**.
3. **4 ключевых экрана на телефоне (360 px)**: каталог, карточка товара, корзина + оформление, главная — **согласование**.
4. **Остальные экраны + планшет и десктоп** (`02`), обе языковые версии, состояния — **согласование**.
5. **Передача в разработку**: токены (`03`), компоненты, шрифты, иконки, картинки — начинаем вёрстку (Этап 2 в коде).
6. Вёрстка идёт **строго по дизайн-системе**; после каждого экрана — проверка на телефоне и в Telegram.

Каждый шаг — маленький: показываю → вы правите → фиксируем. Как и в предыдущих этапах: сначала план, потом код, потом проверка.

## Figma — нужно ли подключать

Figma нужна **только если макеты рисуются в Figma** (вариант 1 или часть варианта 3). Тогда:

- В каталоге подключаемых сервисов Claude есть **коннектор Figma** (в этой сессии он **пока не подключён**). С ним я могу читать ваши макеты: получать структуру и стили кадра, скриншоты, переменные (цвета, размеры, шрифты) и по ним верстать.
- Что нужно от вас: аккаунт Figma, файл с макетами (доступ на просмотр моему подключению), ссылка на кадры. Подключение делается в приложении Claude в разделе коннекторов (Connectors; точные названия пунктов зависят от версии приложения): выбрать **Figma → Подключить** и войти в свой аккаунт Figma. **Пароль от Figma мне присылать не нужно**, вход выполняется на странице Figma.
- Какие функции Figma доступны на бесплатном тарифе, а какие требуют платного места (например, режим разработчика), я **не знаю точно** — уточним при подключении.
- Если макеты рисую я в коде (вариант 2), **Figma не нужна**.

## Git и GitHub — нужно ли (исходное обоснование)

**Для дизайна — нет.** Но есть важная проблема, не связанная с дизайном: **проект сейчас нигде не сохраняется с историей изменений**. На компьютере **не установлен Git** (программа для истории версий), у нового и старого проектов нет истории. Любая ошибка (в том числе моя) или поломка диска может стоить работы, и откатить будет нечем; в этой сессии, например, случайная запись в файл старого проекта откатывалась вручную.

Что рекомендую сделать **в ближайшее время** (это в ТЗ и на пути к запуску):

1. Установить **Git for Windows** (официальный сайт git-scm.com) — я дам пошаговую инструкцию.
2. Создать **приватный репозиторий на GitHub на ваш аккаунт** (ТЗ: «все доступы оформлены на владельца, а не на разработчика»).
3. Сохранить текущее состояние как первый снимок (`.env`, `node_modules`, данные и файлы фидов уже исключены из репозитория в `.gitignore`).
4. Дальше после каждого шага делать снимок с понятным описанием.

Коннектор GitHub для Claude в каталоге подключаемых сервисов **я не нашёл**; и он не нужен: Claude Code работает через обычные команды `git`. Вход в GitHub вы выполняете на своём компьютере в браузере (Git Credential Manager), **пароли и токены мне присылать нельзя**. GitHub понадобится позже также для развёртывания на сервере (Этап 8).
