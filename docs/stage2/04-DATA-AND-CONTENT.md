## Публичный API для витрины (готов, Этап 1)

`GET /api/catalog/search` — параметры:

| Параметр | Что делает |
|---|---|
| `q` | текст: название, артикул (и без нулей), бренд, категория; исправляет раскладку («rheu» → «круг»), понимает опечатки и синонимы (болгарка = УШМ = КШМ и т. п.) |
| `cat` | категория **со всеми вложенными** |
| `brand` | бренд (можно несколько раз) |
| `min`, `max` | цена от и до |
| `avail=1` | только «в наличии» |
| `sale=1` | только со скидкой |
| `f.<код>` | значение характеристики-фильтра (можно несколько раз), коды — ниже |
| `sort` | `relevance`, `price_asc`, `price_desc`, `new`, `name` (товары «в наличии» всегда выше «под заказ») |
| `page`, `per` | страница, штук на страницу (до 60, по умолчанию 24) |

Ответ: `total`, `pages`, `items[]` (id, артикул, названия укр./рус., бренд, цена, старая цена, `discountPct`, `available`, фото-ссылка, категория), `facets` (бренды со счётчиками, **подкатегории со счётчиками**, диапазон цены `min/max`, характеристики-фильтры со значениями и счётчиками, у выбранной группы — и остальные значения), `correctedQuery` (если запрос исправлен по раскладке), `processingMs`.

`GET /api/catalog/suggest?q=…` — до 6 подсказок (название, фото, цена, наличие) для выпадающего списка в шапке; тоже исправляет раскладку.

Скорость: ответ поиска 3–8 мс внутри Meilisearch, весь запрос 50–80 мс (на локальном компьютере).

### Фильтры-характеристики (что вообще может появиться в панели фильтров)

Показываются только те, что есть у товаров выбранной категории (≥ 2 разных значения и ≥ 3 товара). Это **динамический список**, макет должен быть универсальным (группа = заголовок + список значений со счётчиками + «показать ещё»).

| Код | Подпись |
|---|---|
| `series` | Серія (например, «М-Type 18», «SmartLine+» — для аккумуляторов) |
| `diameter` | Діаметр, мм |
| `landing` | Посадковий отвір, мм |
| `drillDiameter` | Діаметр свердла |
| `length` | Довжина, мм |
| `thickness` | Товщина, мм |
| `material` | Матеріал |
| `shank` | Хвостовик |
| `slot` | Тип шліца |
| `packQty` | Кількість в упаковці |
| `voltage` | Напруга, В |
| `power` | Потужність, Вт |
| `engine` | Тип двигуна |
| `fuel` | Паливо |
| `grit` | Зернистість |
| `purpose` | Призначення |
| `type` | Тип |

Плюс общие: бренд, цена, наличие, скидка. Значения бывают длинными («Безщітковий (асинхронний)», до 40 знаков) — предусмотреть перенос/обрезку. Список расширяется (см. `docs/CATALOG-IMPORT.md`).

## Страницы и тексты интерфейса

- **Все тексты интерфейса** (кнопки, подписи, ошибки, названия уровней) уже написаны для рабочего прототипа на **двух языках**: `..\handyman\src\texts.json` (≈ 100 ключей: «Каталог», «Кошик», «У кошик», «Нічого не знайдено», «Часто беруть разом», «Додати комплект», «Оформити замовлення», «Сплатити», «Мої замовлення» и т. д.). Их надо **взять за основу**, чтобы не переписывать заново; новые тексты добавляем в тот же формат.
- Правило проекта: **тексты витрины не зашиваются в код**, а лежат в файле текстов (укр. + рус.) и правятся в админке владельцем. Дизайнеру достаточно указать текст в макете.
- Юридические страницы (оферта, конфиденциальность, возврат и гарантия) — **владелец/юрист**; мы не придумываем. В макете — обычная текстовая страница.

## SEO-ограничения, которые влияют на дизайн

- Адреса понятные (ЧПУ): `/krugy-vidrizni/125-mm-metal/`; украинская версия по умолчанию `/`, русская `/ru/`, теги `hreflang`.
- Посадочные страницы фильтров имеют **свой заголовок H1 и текст**; остальные комбинации фильтров закрыты от индексации.
- Товар «нет в наличии» **не удаляется** (страница остаётся, с «Сообщить о поступлении») — макет карточки «Под заказ» обязателен.
- Хлебные крошки, микроразметка (Product, Offer, AggregateRating, BreadcrumbList) — нужны данные на странице: цена, наличие, рейтинг.
- Сайт рендерится на сервере, изображения — WebP/AVIF, lazy-load.
