# Резервные копии (шаг 8.1)

Коротко: сайт **сам** каждую ночь сохраняет копию базы, фото и ключа шифрования, хранит 14 ежедневных и 8 еженедельных копий,
раз в неделю **сам проверяет**, что копия восстанавливается, и пишет в Telegram, если что-то не так. Смотреть и скачивать — в админке
**«Резервные копии»** (`/admin/backups`, видит только владелец).

## Что входит в копию

| Что | Файл | Зачем |
|---|---|---|
| База (заказы, клиенты, товары, остатки, склад, настройки сайта, сотрудники, ключи «Интеграций» в зашифрованном виде) | `db.dump` | главное |
| Ключ шифрования (`SECRETS_KEY` из `.env` или файл `.data/secrets.key`) | `secrets.key` | без него ключи сервисов из «Интеграций» (бот, mono, Checkbox, KeyCRM…) в копии не прочитать — их пришлось бы вводить заново |
| Описание копии (когда, сколько строк в главных таблицах, результат проверки) | `manifest.json` | для проверки восстановления и списка в админке |
| Фото товаров (папка `MEDIA_DIR`) | папка `media` рядом с копиями | копируются только новые файлы (уже скопированные пропускаются) |

Не копируется: поисковый индекс (после восстановления — `pnpm search:reindex`), скачанные фиды поставщиков (не нужны), файл `.env`
(в нём пароли — храните его отдельно, например в менеджере паролей).

**Ключ шифрования (`secrets.key`) и файл базы — это доступ ко всем данным магазина.** Скачанные копии храните так же бережно, как пароли:
не пересылайте в мессенджерах, не кладите в общие папки.

## Где лежат

- Папка копий — `BACKUP_DIR` из `.env`; если не задана — `.data/backups` в папке проекта. Внутри — по папке на копию:
  `2026-09-28_033000-auto` (дата и время по Киеву; `auto` — ночная, `manual` — вручную, `pre-restore` — перед восстановлением).
- Фото — `BACKUP_DIR/media`.
- На сервере (шаг 8.4) `BACKUP_DIR` — отдельный том/диск.

## Когда и сколько

- **Каждую ночь с 03:30** по Киеву. Если сайт ночью был выключен (компьютер владельца), копия сделается, когда его включат.
  Не получилось — ещё 2 попытки через час, и сообщение в Telegram (в чат менеджеров, как сводки).
- **Хранятся**: самая новая копия за каждый из 14 последних дней (с копиями), самая новая за каждую из 8 последних недель, 5 последних
  сделанных вручную. Старые удаляются сами (и из облака тоже). Правило — `pickBackupsToDrop` в `packages/core/src/backups.ts`.
- **Проверка восстановления — раз в 7 дней с 04:30**: последняя копия восстанавливается во временную базу `<база>_restore_check`
  (рабочую не трогает), сверяется число строк в главных таблицах (товары, заказы, клиенты, склад…), контрольная сумма файла и то, что ключ
  из копии открывает ключи «Интеграций»; временная база удаляется. Не прошла — сообщение в Telegram.
- Кнопки в админке: **«Сделать копию сейчас»**, **«Проверить восстановление»**, у каждой копии — **«Скачать → база / ключ»** (каждое скачивание
  пишется в «Журнал»).

## Вторая копия в облаке (на случай, если сломается весь сервер)

Подходит любое **S3-совместимое** хранилище: Cloudflare R2, Backblaze B2, Wasabi, Amazon S3 и т. п. (какое выбрать — вопрос Д59 в
`docs/QUESTIONS-TO-OWNER.md`). Что сделать владельцу:

1. В кабинете хранилища создать **приватную** корзину (bucket), например `handyman-backups`.
2. Создать ключ доступа только к этой корзине (права: чтение и запись). Записать «Access Key ID» и «Secret Access Key» (секретный показывается один раз).
3. В админке: **«Интеграции» → «Резервные копии: второе хранилище (облако)»** — вписать адрес хранилища (endpoint, есть в кабинете хранилища),
   корзину, оба ключа (регион — только для Amazon S3), нажать **«Проверить подключение»**.
4. Со следующей ночи (или сразу — «Сделать копию сейчас») копия выгружается и туда: `handyman/db/<копия>/…` и `handyman/media/…`.
   Фото выгружаются частями (до 45 минут за ночь) — первая выгрузка большого каталога может занять несколько ночей; в «Резервных копиях» видно,
   сколько осталось.

Без облака копии лежат только на том же компьютере/сервере — в «Резервных копиях» висит предупреждение.

## Восстановление вручную

Когда нужно: сломалась база, перенос на новый сервер (шаг 8.5), нужно вернуть данные «как было вчера».

**Внимание: всё, что сейчас в базе, заменится данными копии.** Перед этим сайт сам делает копию текущей базы (`…-pre-restore`) — если
восстановили не ту копию, можно вернуться к ней той же командой.

### На компьютере владельца (Windows)

1. Остановить сайт: закрыть окно «Сайт Handyman — не закрывайте это окно».
2. Убедиться, что Docker Desktop запущен (зелёный значок).
3. Открыть PowerShell в папке проекта (в Проводнике: папка проекта → в адресной строке набрать `powershell` → Enter).
4. Посмотреть список копий: `dir .data\backups` (или в админке «Резервные копии»).
5. Восстановить: `pnpm backup:restore 2026-09-28_033000-auto --yes` (имя нужной копии). Без `--yes` команда только объяснит, что сделает.
6. Затем: `pnpm db:migrate` (если копия со старой версии сайта), `pnpm search:reindex`, и запустить сайт ярлыком **«Обновить сайт»**.

### На сервере (Docker, шаг 8.4 — `deploy/README.md`)

В папке проекта на сервере (`cd /opt/handyman`):

```bash
C="docker compose -f docker-compose.prod.yml"
$C exec web ls /backups                                        # список копий
$C stop web                                                    # остановить сайт (база и поиск работают)
$C run --rm web backup-restore 2026-09-28_033000-auto --yes     # имя нужной копии
$C up -d web                                                   # запустить: база сама обновится до текущей версии
$C exec web hm reindex                                         # пересобрать поиск
```

Копия с другого компьютера (переезд с ПК) — одной командой `bash deploy/move-from-pc.sh <папка копии>` (`docs/LAUNCH.md`); вручную — в том копий:
`$C cp ./2026-09-28_120000-manual web:/backups/` (сайт при этом запущен). Обратно, с сервера на ПК — `bash deploy/export-for-pc.sh`.

### С другого компьютера / из облака

Скопировать папку копии (с файлами `db.dump`, `secrets.key`, `manifest.json`) и, если нужно, папку `media` в `BACKUP_DIR` на новом месте
(папки рядом: `…/backups/<копия>` и `…/backups/media`), затем — как выше. Из облака — скачать `handyman/db/<копия>/` и `handyman/media/`
программой хранилища (например, Cyberduck или rclone).

Что делает `restore`: проверяет контрольную сумму файла, делает копию текущей базы (если в ней есть данные; отключить — `--no-safety`),
восстанавливает базу, кладёт ключ шифрования на место (прежний файл ключа откладывает рядом: `secrets.key.before-restore-…`; если ключ задан
переменной `SECRETS_KEY` и не совпадает — говорит, что вписать), копирует фото, которых нет в `MEDIA_DIR`.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm backup:now` | сделать копию сейчас (как кнопка в админке) |
| `pnpm backup:check [имя]` | проверить восстановление во временную базу (рабочую не трогает) |
| `pnpm backup:restore <копия> --yes` | восстановить копию в рабочую базу (см. выше) |

## Откуда берётся `pg_dump`

Одна функция `pgRunner()` в `packages/db/src/backups.ts`, по порядку:
1. `PG_BIN_DIR` в `.env` — папка с `pg_dump`/`pg_restore`;
2. `pg_dump` на этом компьютере (на сервере — в образе сайта: `apps/web/Dockerfile` ставит `postgresql-client-16` из пакетов Ubuntu 24.04);
3. Docker: `docker exec handyman-next-postgres-1 pg_dump …` (компьютер владельца; имя контейнера — `PG_DOCKER_CONTAINER`).
Версия `pg_dump` должна быть не старше сервера базы (сейчас PostgreSQL 16).

## Для разработчика

- Модули: `packages/core/src/backups.ts` (имена, правило хранения, расписание, сверка строк, подпись S3 — с тестами),
  `packages/db/src/backups.ts` (копия, проверка, восстановление, список; запуск из `runJobs` → `runBackupJobs`),
  `packages/db/src/offsite.ts` (облако; в тестах сеть — `setOffsiteFetch`), страница `apps/web/app/admin/(panel)/backups/`.
- Список копий — папки в `BACKUP_DIR` с `manifest.json`; таблиц в базе нет. В `Setting`: `backup.lock` (идёт копия/проверка — одна на все копии
  сайта; зависшая снимается через 3 часа), `backup.lastAttempt` (попытки ночной копии за день), `backup.lastCheck` (последняя проверка).
- Копия «перед восстановлением» не удаляет чисткой ту копию, из которой восстанавливают (`createBackup({ keep })` → `pruneBackups(keep)`;
  иначе старая копия, перенесённая с ПК, при 5+ более новых «ручных» пропадала до восстановления — найдено на шаге 8.4).
- В тестах ночные копии из `runJobs` выключены (`HM_BACKUPS=off` в `test/helpers.ts`); тест копий включает их сам и пишет во временную папку.
- Новая важная таблица — добавить в `BACKUP_CHECK_TABLES` (сверка числа строк при проверке).
