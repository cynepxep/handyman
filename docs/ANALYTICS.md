# Аналитика и реклама: как подключить (шаги А2–А3)

Инструкция для владельца: Google Analytics 4, Google Tag Manager, Google Ads, Meta (Facebook/Instagram) Pixel, TikTok Pixel.
Сайт к ним уже готов (шаг А1), готовый набор тегов лежит в файле (шаг А2). Ваша часть — **создать аккаунты, скопировать из них ID,
импортировать один файл и вписать ID в админке**. Программист для этого не нужен.

> **Про кнопки в кабинетах.** Google, Meta и TikTok часто переименовывают и переставляют пункты меню. Ниже написано, *что* нужно найти;
> где путь указан точно, он проверен по справке сервиса, а где написано «примерно так» — названия кнопок могут отличаться. Если не нашли пункт —
> напишите Claude, что видите на экране (или пришлите снимок), подскажем.

Проверять «вживую» лучше на настоящем домене (шаг А6 в `docs/PLAN-TO-LAUNCH.md`, раздел «Аналитика» в `docs/LAUNCH-CHECKLIST.md`).
Аккаунты, ID и импорт можно сделать заранее, хоть сейчас.

---

## 1. Как это устроено

```
Сайт ──► dataLayer (события: просмотр товара, корзина, покупка…) ──► Google Tag Manager ──► GA4
                                                                                   ├──► Google Ads (покупка, ремаркетинг)
                                                                                   ├──► Meta Pixel
                                                                                   └──► TikTok Pixel
```

- На сайт ставится **только Google Tag Manager** (GTM) — «коробка с тегами». Сайт сообщает в неё события, а она раздаёт их кабинетам.
- **ID всех кабинетов вписываются в админке сайта** («Настройки → Интеграции → Аналитика и реклама»), а не в GTM: сайт сам передаёт их в
  контейнер. Поменяли ID или подключили новый кабинет — только поле в админке, контейнер трогать не нужно.
- Пустое поле — теги этого кабинета просто не срабатывают. Можно начать с одного GA4, а рекламу подключить позже.
- **Суммы считает сервер** (как в заказе), покупка отправляется **один раз на заказ**. Тестовые заказы, «подозрительные» (чёрный список)
  и заказы из браузера, где вы вошли в админку, **не считаются**. Более того: в браузере с входом в админку GTM не загружается вовсе —
  поэтому проверять аналитику нужно в окне «инкогнито» или на телефоне без входа в админку.
- «Купити в 1 клік» тоже считается покупкой (это настоящий заказ HM-…, вопрос Д80).
- **Покупка ещё и с сервера** (шаг А3, необязательно): часть покупок браузер не передаёт (блокировщики рекламы, iPhone), поэтому сайт сам
  отправляет каждую покупку в Meta, TikTok и GA4 напрямую — если вписаны их ключи (раздел 13). Кабинеты склеивают её с покупкой из браузера
  по номеру заказа — **дважды не считается**.

## 2. Порядок действий

1. Google Tag Manager — аккаунт и контейнер → ID вида `GTM-ABC1234` (раздел 3).
2. Google Analytics 4 — ресурс и поток → ID вида `G-ABC123DEF4` (раздел 4).
3. Вписать эти два ID в админке, нажать «Проверить подключение» и «Включить» (раздел 7).
4. Скачать готовый контейнер и импортировать его в GTM, опубликовать (раздел 8).
5. Когда будете запускать рекламу: Google Ads (раздел 5), Meta (раздел 6.1), TikTok (раздел 6.2) — каждый ID вписать в админке.
6. Проверить (раздел 9) — на домене, вместе с чек-листом запуска.

Все аккаунты Google (GTM, GA4, Ads, Search Console) — **на одной вашей почте Google**: так их проще связать между собой.

## 3. Google Tag Manager

1. Откройте <https://tagmanager.google.com> и войдите своей почтой Google.
2. «Создать аккаунт»: название аккаунта — `Handyman`, страна — Украина.
3. Контейнер: название — адрес сайта (например `handyman.com.ua`; домена пока нет — просто `Handyman`), платформа — **«Веб» (Web)**.
4. Примите условия. GTM покажет окно с кодом для вставки на сайт — **его никуда вставлять не нужно** (сайт уже умеет), окно можно закрыть.
5. Скопируйте ID контейнера — он вверху рядом с названием, вида `GTM-ABC1234`.

## 4. Google Analytics 4

1. Откройте <https://analytics.google.com>, нажмите «Начать измерения» (или «Администратор» → «Создать» → «Ресурс», если аккаунт уже есть).
2. Аккаунт — `Handyman`. Ресурс — `Handyman`, **часовой пояс — Украина (Киев), валюта — украинская гривна (UAH)**.
3. Сведения о компании — по желанию (розничная торговля, малый бизнес).
4. Платформа — **«Веб»**: адрес сайта (пока домена нет — можно вписать будущий), название потока — `Сайт`.
5. В настройках потока «Расширенная статистика» (Enhanced measurement) — **оставьте включённым** (особенно «Просмотры страниц» и в их
   дополнительных настройках — «Изменения страницы на основе событий истории браузера»: сайт открывает страницы без перезагрузки, так GA4 их
   видит). «Поиск по сайту» можно оставить — сайт и так присылает своё событие `search`.
6. **Устанавливать код не нужно**, пропустите этот шаг («установка вручную» / «Google Tag Manager» — окно просто закрыть).
7. Скопируйте **идентификатор потока** вида `G-ABC123DEF4` («Администратор» → «Потоки данных» → ваш поток).

Настройки после создания («Администратор»), один раз:

| Что | Где (примерно так) | Зачем |
|---|---|---|
| Хранение данных — **14 месяцев** | «Сбор и изменение данных» → «Хранение данных» | по умолчанию 2 месяца — мало для сравнения с прошлым годом |
| `purchase` — **ключевое событие** | «Отображение данных» → «События» / «Ключевые события» | покупка — главная цель. Обычно GA4 отмечает `purchase` сам — проверьте, что звёздочка/переключатель включены (событие появится в списке после первой покупки) |
| Пользовательские параметры | «Отображение данных» → «Специальные определения» → «Создать специальный параметр» | чтобы видеть в отчётах: `channel` (сайт или Telegram Mini App), `click_location` (где нажали телефон), `messenger` (Telegram или Viber), `page_type` (тип страницы). Область — «Событие», название и параметр — одинаковые |
| Связь с Google Ads | «Связь с другими продуктами» → «Связь с Google Ads» | когда появится аккаунт Ads (раздел 5) |

## 5. Google Ads — конверсия «Покупка»

Нужно, когда запускаете рекламу в Google. В контейнере уже есть: конверсия «Покупка» (сумма, валюта, номер заказа), ремаркетинг
(списки посетителей для показа рекламы) и Conversion Linker (запоминает клик по объявлению).

1. <https://ads.google.com> — аккаунт рекламодателя (валюта аккаунта — гривна; поменять потом нельзя).
2. «Цели» → «Конверсии» → «Создать действие-конверсию» (примерно так) → **«Веб-сайт»**.
3. Если предложит «просканировать сайт» — можно пропустить и выбрать **«Добавить действие-конверсию вручную»**.
4. Настройки:
   - категория — **«Покупка»**;
   - название — `Покупка на сайте`;
   - ценность — **«Использовать разные ценности для каждой конверсии»** (значение по умолчанию — любое, например 1 UAH);
   - подсчёт — **«Каждая»** (каждая покупка — отдельная конверсия);
   - остальное — по умолчанию.
5. Способ установки тега — **«Использовать Google Tag Manager»**. Google покажет два значения:
   - **идентификатор конверсии** — цифры (в админку вписывайте с приставкой: `AW-123456789`);
   - **метка конверсии** — вида `AbC-dEf_123`.
6. Оба значения — в админку (раздел 7), поля «Google Ads: идентификатор конверсии» и «метка конверсии „Покупка“».
7. Свяжите Google Ads с GA4 (раздел 4, последняя строка таблицы).

> **Не считайте покупку дважды.** Покупку в Google Ads уже передаёт тег из контейнера. Если после связи с GA4 Google предложит
> «импортировать конверсии из Google Analytics» — `purchase` из GA4 либо не импортируйте, либо сделайте её **второстепенной** (не основной),
> иначе в отчётах Ads каждая покупка будет дважды.

Динамический ремаркетинг (объявления с конкретными товарами) — позже, ему нужен фид товаров в Google Merchant Center (отдельная задача).

## 6. Пиксели Meta и TikTok

### 6.1. Meta Pixel (Facebook и Instagram)

1. <https://business.facebook.com> — бизнес-портфолио (Meta Business Suite) на вашу компанию.
2. **Events Manager** (Менеджер событий) → «Подключить источники данных» → **«Веб»** → «Пиксель» (в новых версиях — «Набор данных», dataset;
   это одно и то же) → название `Handyman`.
3. Способ установки — **не нужен**: если спросит, выберите «установить код вручную» и просто закройте окно с кодом.
4. Скопируйте **ID пикселя** — только цифры (обычно 15–16), виден в Events Manager под названием пикселя.
5. Желательно: подтвердить домен — «Настройки компании» → «Безопасность бренда» → «Домены» (примерно так; Meta даст мета-тег или запись DNS —
   пришлите его Claude, добавим).

Какие события получит Meta: `PageView` (каждая страница), `ViewContent` (карточка товара), `AddToCart`, `InitiateCheckout` (оформление),
`Purchase` (покупка, `eventID` = номер заказа HM-…), `Search`, `AddToWishlist` (сердечко «Обране»), `Contact` (нажали телефон, Telegram или Viber).

### 6.2. TikTok Pixel

1. <https://ads.tiktok.com> — рекламный кабинет TikTok Ads Manager.
2. «Инструменты» (Tools) → **«События»** (Events) → «Веб-события» (Web events) → «Настроить веб-события» → способ — **вручную**
   (Manual / «Установить код пикселя самостоятельно»; примерно так).
3. Название — `Handyman`. Код пикселя устанавливать не нужно — окно закрыть.
4. Скопируйте **ID пикселя** — латинские буквы и цифры, вида `C1ABCDEF2GHIJ3KLMN4O`.

Какие события получит TikTok: просмотр страницы, `ViewContent`, `AddToCart`, `InitiateCheckout`, `CompletePayment` (покупка, `event_id` = номер
заказа), `Search`, `AddToWishlist`, `Contact`.

## 7. Вписать ID в админке

1. Админка → «Настройки» → **«Интеграции»** → блок **«Аналитика и реклама (Google Tag Manager)»** (видит только владелец).
2. Впишите, что есть (пустые поля — можно позже):
   - ID контейнера Google Tag Manager — `GTM-…` (**обязательно**, без него ничего не загружается);
   - Google Analytics 4 — `G-…`;
   - Google Ads — `AW-…` и метку конверсии;
   - Meta Pixel — цифры; TikTok Pixel — буквы и цифры.
3. «Сохранить». Неверный формат — админка подскажет, как должен выглядеть ID.
4. «Проверить подключение» — спрашивает Google, **опубликован** ли контейнер (до публикации, раздел 8, будет «не прошла» — это нормально).
5. **«Включить»** (переключатель «Аналитика: выключена → включена»). Выключить можно в любой момент той же кнопкой — сайт сразу перестаёт
   загружать GTM.

## 8. Импорт готового контейнера в GTM

Файл с готовыми тегами: кнопка **«⬇ Скачать готовый контейнер для Tag Manager»** в том же блоке «Интеграции → Аналитика и реклама»
(или файл `deploy/gtm-container.json` в папке проекта — это одно и то же).

1. GTM → вкладка **«Администрирование»** (Admin) → в колонке контейнера **«Импортировать контейнер»** (Import Container).
2. «Выбрать файл контейнера» → скачанный файл `handyman-gtm-container-….json`.
3. Рабочая область — **«Существующая»** → `Default Workspace` (рабочая область по умолчанию).
4. Вариант импорта — **«Объединить»** (Merge) → **«Переименовать конфликтующие теги, триггеры и переменные»**.
   (В новом пустом контейнере конфликтов нет. «Перезаписать» стирает всё, что было в контейнере, — для первого импорта не нужно.)
5. GTM покажет, сколько тегов, триггеров и переменных добавится (примерно 33 тега, 18 триггеров, 21 переменная) → «Подтвердить».
6. Вверху справа **«Отправить»** (Submit) → название версии, например `Handyman 2026-10-04` → **«Опубликовать»** (Publish).
7. Вернитесь в админку и нажмите «Проверить подключение» — теперь должно быть «проверка прошла».

**Ничего в тегах вписывать не нужно** — ID они берут с сайта. Папки в контейнере: «GA4», «Google Ads», «Meta Pixel», «TikTok Pixel»
и «Handyman — переменные и триггеры».

**Новая версия контейнера** (если Claude поменяет теги — в админке у кнопки будет другая дата): скачать файл заново → импорт → «Объединить» →
**«Перезаписать конфликтующие теги, триггеры и переменные»** → «Отправить» → «Опубликовать». Свои теги, если добавляли, при этом останутся.

## 9. Проверка

Пока домена нет, можно проверить на компьютере, где запущен сайт (адрес `http://localhost:3100`), но **в окне «инкогнито»** (без входа
в админку). Окончательная проверка — на домене (шаг А6, раздел «Аналитика» в `docs/LAUNCH-CHECKLIST.md`).

1. **Предпросмотр GTM** (Tag Assistant): в GTM кнопка «Предварительный просмотр» (Preview) → адрес сайта → «Connect». Откроется сайт
   в отдельном окне, а в окне Tag Assistant слева — список событий, справа — какие теги сработали («Tags Fired»). Что должно срабатывать:

   | Что сделать на сайте | Событие слева | Теги «Fired» (если ID вписан) |
   |---|---|---|
   | открыть любую страницу | Container Loaded / `gtm.js` | GA4 — тег Google; Google Ads — Conversion Linker, ремаркетинг; Meta — пиксель; TikTok — пиксель |
   | перейти на другую страницу | History | Meta — PageView (переход), TikTok — page (переход), Google Ads — ремаркетинг |
   | открыть товар | `view_item` | GA4 — view_item, Meta — ViewContent, TikTok — ViewContent |
   | открыть раздел или поиск | `view_item_list`, `search` | GA4 — view_item_list / search, Meta — Search, TikTok — Search |
   | нажать на товар в списке | `select_item` | GA4 — select_item |
   | «У кошик» / «+» | `add_to_cart` | GA4 — add_to_cart, Meta — AddToCart, TikTok — AddToCart |
   | «−» / убрать из корзины | `remove_from_cart` | GA4 — remove_from_cart |
   | открыть оформление | `begin_checkout` | GA4 — begin_checkout, Meta — InitiateCheckout, TikTok — InitiateCheckout |
   | оформить заказ («Дякуємо») | `purchase` | GA4 — purchase, Google Ads — конверсия «Покупка», Meta — Purchase, TikTok — CompletePayment |
   | обновить «Дякуємо» | — | **ничего** (покупка один раз) |
   | сердечко «Обране» | `add_to_wishlist` | GA4 — add_to_wishlist, Meta — AddToWishlist, TikTok — AddToWishlist |
   | нажать телефон / Telegram / Viber | `phone_click` / `telegram_click` | GA4 — phone_click / telegram_click, Meta — Contact, TikTok — Contact |

   Тег в разделе «Not Fired» при вписанном ID — пришлите Claude снимок. Теги кабинета без ID всегда в «Not Fired» — так и должно быть.
2. **GA4 → «Администратор» → DebugView** — во время Предпросмотра события появляются там через несколько секунд. Обычные отчёты GA4
   заполняются с задержкой до суток; «Отчёты → В реальном времени» — сразу.
3. **Meta → Events Manager → ваш пиксель → «Тестирование событий»** (Test Events) → адрес сайта → «Открыть сайт» → события появляются в списке.
   Удобно ещё расширение браузера **Meta Pixel Helper**.
4. **TikTok → Events Manager → пиксель → «Тестовые события»** (Test Events) — так же. Расширение — **TikTok Pixel Helper**.
5. **Google Ads → «Цели» → «Конверсии»** — статус конверсии «Покупка» меняется с «Не проверено» на «Запись конверсий» через несколько часов
   после первой настоящей покупки.

Проверочные заказы после проверки — **отменить** в админке (причина «тест»). В рекламных кабинетах такая покупка уже посчитана —
это нормально для одной-двух проверок (проверить покупку без настоящего заказа нельзя: заказ из браузера с админкой — «тестовый», и теги на нём
не срабатывают). Удобно совместить с настоящим платежом 10 ₴ из чек-листа запуска.

## 10. Что в контейнере

| Папка | Тег | Когда срабатывает |
|---|---|---|
| GA4 | GA4 — тег Google | каждая страница (просмотры страниц считает GA4) |
| GA4 | GA4 — `view_item`, `view_item_list`, `select_item`, `add_to_cart`, `remove_from_cart`, `begin_checkout`, `purchase`, `search`, `phone_click`, `telegram_click`, `add_to_wishlist` | на одноимённое событие сайта; товары и суммы — из `dataLayer` (формат GA4 e-commerce, `item_id` = артикул), у каждого параметр `channel` |
| Google Ads | Conversion Linker | каждая страница |
| Google Ads | конверсия «Покупка» | `purchase`: сумма (товары после скидок, без доставки), UAH, номер заказа |
| Google Ads | ремаркетинг | каждая страница и переход по сайту |
| Meta Pixel | пиксель (основной код) | первая страница (официальный код пикселя + `PageView`) |
| Meta Pixel | PageView (переход), ViewContent, AddToCart, InitiateCheckout, Purchase, Search, AddToWishlist, Contact | переходы и события сайта (таблица в разделе 9) |
| TikTok Pixel | пиксель (основной код) | первая страница (официальный код пикселя + просмотр страницы) |
| TikTok Pixel | page (переход), ViewContent, AddToCart, InitiateCheckout, CompletePayment, Search, AddToWishlist, Contact | так же |

Триггеры «Блок — нет ID …» — исключения: если ID кабинета не вписан в админке, его теги не срабатывают.
Meta и TikTok сделаны тегами «Пользовательский HTML» с официальным кодом пикселей (а не шаблонами из галереи GTM): код виден целиком,
проверяется тестами и не меняется сам при обновлениях галереи.

## 11. Чего не делать

- **Не вставлять** коды GA4, пикселей или GTM на сайт ещё раз (через «Сайт → Страницы» или по советам кабинетов) — всё уже идёт через GTM,
  второй код удвоит статистику.
- **Не добавлять** в GTM второй тег GA4 или вторую конверсию покупки Google Ads.
- **Не включать** в Meta/TikTok «автоматическую настройку событий по нажатиям» (Event Setup Tool / автоматические события) для покупки — покупку
  присылает сайт.
- Не удивляться, что в браузере с открытой админкой ничего не считается: так задумано (ваши проверки и работа не засоряют рекламу).

## 12. Если что-то не так

| Что видно | Что сделать |
|---|---|
| «Проверить подключение» — «не прошла» | контейнер не опубликован (раздел 8, шаг 6) или ID с опечаткой |
| В Предпросмотре сайт открылся, но событий нет | вы вошли в админку в этом браузере — откройте Предпросмотр в «инкогнито»; или аналитика выключена в «Интеграциях» |
| Тег кабинета «Not Fired», хотя ID вписан | сохранили ли ID («Сохранить»)? Обновите страницу сайта; если не помогло — снимок Предпросмотра Claude |
| Покупка в GA4 есть, в Google Ads — нет | вписаны ли оба поля Google Ads (идентификатор **и** метка)? Конверсия появляется в Ads через несколько часов |
| В Ads покупок вдвое больше | импортирована `purchase` из GA4 как основная — сделать второстепенной (раздел 5) |
| Импорт контейнера выдаёт ошибку | текст ошибки (снимок) — Claude: файл собран по формату экспорта GTM, но в настоящий GTM из облака его загрузить не могли |
| В заказе блок «Реклама: покупка с сервера» — «не ушло» | текст ошибки там же. «Invalid OAuth access token» / «Access token invalid» — токен неверный или отозван: создайте новый (раздел 13) и вставьте в «Интеграциях» — покупки последних 6 дней уйдут сами |
| В Meta или TikTok покупок вдвое больше | в «Тестировании событий» у покупки должно быть «Дедуплицировано» / «Deduplicated»; если нет — снимок Claude (у браузерной и серверной покупки должен совпадать номер заказа) |
| В GA4 покупок или выручки вдвое больше | удалите в «Интеграциях» секрет GA4 (кнопка у поля) — покупки в GA4 останутся только из браузера; напишите Claude |

## 13. Покупка с сервера: Meta Conversions API, TikTok Events API, GA4 (шаг А3)

**Зачем.** Блокировщики рекламы и iPhone (Safari) часть покупок в браузере «съедают» — реклама видит меньше продаж, чем есть, и хуже
находит покупателей. Сервер сайта сам сообщает о каждой покупке напрямую в кабинеты. Это **необязательно**: без ключей всё работает как раньше.

**Как работает.**
- Заказ оформлен (сайт или «1 клік»), аналитика включена → сразу после заказа сервер отправляет покупку в каждый кабинет, для которого вписан ключ.
  Покупатель этого не ждёт и не замечает. Нет связи — сайт повторяет сам (через 1, 5, 15, 60 минут, 3 и 12 часов).
- **Дважды не считается**: у покупки из браузера и с сервера один и тот же номер заказа (HM-…), кабинеты по нему склеивают их в одну
  (в Meta это называется «дедупликация»). Для GA4 сервер передаёт тот же идентификатор посетителя, что и браузер (из куки `_ga`).
- Телефон и почта покупателя уходят в Meta и TikTok **только в зашифрованном виде** (SHA-256 — так требуют кабинеты; расшифровать нельзя,
  кабинет лишь сравнивает со своими пользователями). В Google Analytics телефон не уходит вовсе. Вопрос Д77.
- Ещё уходят куки рекламы (`_fbp`, `_fbc`, `_ttp`, `_ga`), адрес (IP) и браузер покупателя — по ним кабинет связывает покупку с кликом по рекламе.
  Адрес и браузер стираются из заказа, как только покупка ушла.
- **Не уходят**: тестовые заказы, «подозрительные» (чёрный список), заказы по звонку (это не покупка на сайте).
- **Отмена или возврат заказа** → в Google Analytics уходит «возврат» (`refund`) на всю сумму — выручка в отчётах честная (вопрос Д75).
  В Meta и TikTok отмену не передают (так там не принято).
- Куда ушла покупка — в карточке заказа, блок **«Реклама: покупка с сервера»** («принято», «в очереди», «не ушло» с причиной).
  Сводка за 7 дней — в «Интеграциях → Аналитика и реклама», строка «Покупка с сервера».

**Где взять ключи** (вписываются в «Интеграции → Аналитика и реклама», шифруются, видны маской):

| Кабинет | Поле в админке | Где взять (примерно так — названия кнопок могут отличаться) |
|---|---|---|
| Meta | «Meta: токен Conversions API» | Events Manager → ваш пиксель → «Настройки» → раздел «Conversions API» → «Создать маркер доступа» (Generate access token). Нужен и ID пикселя (раздел 6.1) |
| TikTok | «TikTok: токен Events API» | TikTok Ads Manager → «Инструменты» → «Events» → ваш пиксель → «Настройки» → «Сгенерировать токен доступа» (Generate Access Token). Нужен и ID пикселя (раздел 6.2) |
| Google Analytics 4 | «Google Analytics 4: секрет API Measurement Protocol» | «Администратор» → «Потоки данных» → ваш сайт → «Секретные ключи API Measurement Protocol» → «Создать» → скопировать **значение** (не название). Нужен и идентификатор потока `G-…` (раздел 4) |

Токены — как пароль: никому не пересылайте, только в админку. Отзовёте токен в кабинете — покупки перестанут уходить (в заказе будет «не ушло»).

**Проверка.**
1. «Проверить подключение» в «Интеграциях»: Meta проверяет токен (покажет название пикселя), GA4 — формат покупки. TikTok так проверить нельзя —
   только настоящей покупкой.
2. **Meta**: Events Manager → пиксель → «Тестирование событий» → скопируйте **код тестовых событий** (вида `TEST12345`) в поле «Meta: код тестовых
   событий» → оформите заказ в «инкогнито» → в списке появятся две покупки «Purchase»: из браузера и с сервера, у серверной — пометка
   «Дедуплицировано» (или одна с источниками «Браузер» и «Сервер»). **После проверки код удалите** (кнопка у поля), иначе настоящие покупки
   попадут только в «тестовые».
3. **TikTok**: так же — «Тестовые события» → код → поле «TikTok: код тестовых событий» → заказ → удалить код.
4. **GA4**: «Отчёты → В реальном времени» — покупка одна (не две). DebugView серверные события не показывает.
5. В карточке проверочного заказа — блок «Реклама: покупка с сервера»: везде «принято». Отмените заказ — в GA4 через несколько часов появится возврат.

На компьютере разработки без ключей в блоке заказа будет «заглушка (ключа нет)» — в сеть ничего не уходит; на сервере без ключа этот кабинет
просто пропускается.

(по ответу Д74; тогда и покупка с сервера будет учитывать выбор покупателя).
