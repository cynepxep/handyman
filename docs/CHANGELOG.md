## Фото товаров: не показываются на сайте, «чужие» фото после загрузки не того файла (2026-09-28, жалоба владельца)

## Этап 3, шаг 3.5 (часть «KeyCRM») — заказы в KeyCRM и статусы обратно (2026-09-29, вне очереди: Нова Пошта 3.4 — потом)

- **Отправка заказа.** Новый заказ с сайта, «Купити в 1 клік» и «Заказ по звонку» сам уходит в KeyCRM (`POST /order`): источник (`sourceId` из «Интеграций»),
  номер сайта как «номер в источнике» (`source_uuid` = HM-0001), покупатель и телефон, товары (артикул, название, количество, **цена за штуку уже со
  скидкой** — из заказа, посчитана сервером), доставка (Нова Пошта: город и отделение / курьер НП; курьер по Одессе; самовывоз — адрес магазина;
  «1 клік» — без доставки), комментарий покупателя, комментарий менеджеру (оплата, предоплата, скидка, «не звонить», сумма на сайте). Если в «Интеграциях»
  задан ID службы «Нова Пошта» в KeyCRM — ещё и код отделения (`warehouse_ref`). Покупатель не ждёт: отправка идёт после оформления.
- **Без дублей и с повторами.** Очередь — поля `Order.keycrm*` (миграция `20260929090000_keycrm_sync`, только добавления). Отправку берёт одна попытка
  (кнопка, фоновая задача, вторая копия сайта не отправят дважды). Не вышло — `runJobs` повторяет через 1, 2, 5, 10, 30, 60, 120 минут; после 8 попыток —
  тревога менеджерам и кнопка. Если ответ KeyCRM потерялся (заказ мог создаться), перед повтором сайт ищет заказ в KeyCRM по номеру.
- **В заказе админки** — блок «KeyCRM»: передан (№, номер в источнике, статус в KeyCRM) / ждёт / ошибка (причина, когда повтор), кнопка «Отправить в KeyCRM» /
  «Отправить ещё раз» (работает и при выключенной передаче).
- **Тестовые заказы** сами не уходят никогда. Для проверки связи — кнопка в тестовом заказе с галочкой «Отправить тестовый заказ с пометкой «ТЕСТ»»:
  номер TEST-HM-…, первая строка комментария «🧪 ТЕСТ — не обрабатывать».
- **«Интеграции → KeyCRM»** (`/admin/integrations/keycrm`, только владелец): переключатель «Передавать заказы в KeyCRM» (**по умолчанию выключен** — старый
  магазин тоже шлёт заказы), счётчики (передано / ждут / с ошибкой), **таблица соответствия статусов** KeyCRM → сайт (список загружается кнопкой из KeyCRM,
  подсказка по названию, «не менять»), адрес вебхука, последние вебхуки. В карточке KeyCRM раздела «Интеграции» — новое поле «Служба «Нова Пошта» в KeyCRM (ID)».
- **Статусы из KeyCRM.** Вебхук `/api/keycrm/webhook?secret=…` (секрет — «Секрет вебхука» из «Интеграций»; можно заголовком X-Webhook-Secret; без секрета,
  с неверным или шаблонным `change-me-too` — 403) и запасной опрос `GET /order/{id}` раз в 10 минут (пока у сайта нет https-адреса). Статус на сайте меняется
  по таблице через `setOrderStatus` (склад, история «Статус: … (KeyCRM)»). Есть авто-шаблон для этого статуса — сообщение покупателю уходит само; нет —
  запись `PendingNotif` и плашка в заказе «статус сменили в KeyCRM — напишите покупателю» (уходит после отправки сообщения или кнопкой «Не нужно писать»)
  + сообщение менеджерам. Первый раз узнанный при опросе статус только запоминается (чтобы «Новий» не откатил уже оплаченный заказ). В журнал вебхуков —
  без телефона и адреса.
- Код: `packages/core/src/shop/keycrm.ts` (тело запроса, разбор ответов и вебхука, статусы, повторы), `packages/db/src/keycrm.ts` (очередь, отправка, статусы,

## Этап 3, шаг 3.3 — кассовые чеки Checkbox (2026-09-28)

- **Чек сам после оплаты**: каждая настоящая оплата картой через monobank (кнопка «Сплатити», счёт менеджера) — **чек продажи** в Checkbox;
  возврат денег кнопкой «Вернуть деньги…» — **чек возврата** (со ссылкой на чек продажи). Чек ставится в той же транзакции, что и зачисление
  оплаты, — ровно один чек на одну оплату, даже если уведомление mono и опрос пришли одновременно. Тестовая оплата (без токена mono) чека не получает.
- **Что в чеке**: вся сумма заказа одним платежом — **построчно** (товары, количество, цены); предоплата, доплата, часть — одной строкой
  «Передплата за замовлення HM-…» / «Оплата замовлення HM-…» (Д47). Оплата — «Картка» (безнал); у клиента есть почта — Checkbox шлёт чек и на почту.
- **Смена кассира** открывается сама перед первым чеком дня и **закрывается в 23:00** по Киеву (фоновая задача, раз в сутки; Z-отчёт делает Checkbox).
- **Сбои**: Checkbox недоступен или ответил ошибкой — сайт повторяет сам (через 1, 2, 5, 10, 30, 60, 120 минут); после 8 попыток — «не создан»,
  строка в истории заказа и тревога менеджерам «🧾❗ Чек по HM-… не создан». Повтор не создаст второй чек: номер чека в Checkbox задаёт сайт,
  и перед повтором сайт сначала спрашивает, не дошёл ли чек. Если отказала налоговая (ERROR) — сразу «не создан».
- **Покупателю**: как только у чека есть фискальный номер — сообщение в Telegram «Касовий чек за замовлення HM-… (N ₴): ссылка» (нет бота —
  строка «скопируйте» в заказе), ссылка «Касовий чек на N ₴» на странице заказа. Тексты — «Сайт → Тексты», группа «Оплата» (3 новых ключа).

  через терминал — для самовывоза и заказов по звонку; право «Заказы: редактирование»).
- **Без ключей Checkbox**: на компьютере разработки — **тестовые чеки** (номер «ТЕСТ-…», в налоговую не уходят, ссылки покупателю нет), в production —

- Код: `packages/core/src/shop/receipts.ts` (строки чека, тело запроса в копейках/тысячных, разбор ответов и ошибок, расписание повторов, форма ручного чека),

## Этап 3, шаг 3.2 — оплата картой через monobank (2026-09-28)

- **Покупатель**: после оформления с «Передплата» или «Повна оплата онлайн» на странице заказа — **«Сплатити 200 ₴»** → страница оплаты monobank →
  обратно на страницу заказа. Там: «Чекаємо підтвердження оплати від банку…» (страница сама спрашивает раз в 5 секунд, до 3 минут) и кнопка
  «Я сплатив(ла), перевірити»; после подтверждения — «Оплату отримано… Сплачено: 200 ₴». Не прошла или истёк срок ссылки (24 часа) — «Спробувати ще раз».
  Вернулся, не заплатив, — та же ссылка, новый счёт не создаётся. **Сумма — только с сервера**: предоплата — до суммы предоплаты (остаток при получении),
