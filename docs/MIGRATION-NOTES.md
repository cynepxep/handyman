# Соответствие старой схемы (SQLite) и новой (PostgreSQL/Prisma)

Старый проект: `../handyman` (Node.js без зависимостей, `node:sqlite`, два HTML-файла).
Новый: этот репозиторий (Next.js + PostgreSQL/Prisma), переписывается по этапам —
план и прогресс см. `docs/09-ROADMAP.md` в старом проекте и файл плана Этапа 0
(`C:\Users\Дима\.claude\plans\inherited-wibbling-teacup.md` на момент написания).

Старый проект **не трогается и продолжает работать**, пока новый не будет готов
к переключению (свой сервер, свои данные — скопированная копия `data/handyman.db`
использовалась только для проверки количества данных, миграция самих данных ещё
не выполнялась, см. ниже).

## Изменения схемы на Этапе 1 (каталог)

| Что | Зачем |
|---|---|
| `Product.supplierAvailable` | есть ли товар **у поставщика** (в фиде Vitals — только признак, не количество); собственный остаток — `StockItem` (Этап 4) |
| `Product.articleCode`, `Product.supplierUrl` | второй артикул и страница товара у поставщика (из фида) |
| `Product.missingFromFeedSince` | с какого импорта товара нет в фиде (товар остаётся на сайте как «Под заказ») |
| `ProductAttribute.sort` | порядок характеристик как в фиде |
| `Product.purchasePrice` | закупочная цена (наша), вводится вручную; импорт не трогает |
| Категория `unsorted` (запись в `Category`, создаётся кодом) | «Нераспределённые»: товары без категории в фиде; не показываются покупателям |
| `Supplier.feedUrl`, `Supplier.defaultBrand` | ссылка на фид; бренд для товаров, у которых в фиде нет `vendor` (у Vitals его нет вообще) |
| `FeedCategoryMap` | ключ теперь (`supplierId`, `path`); `categoryId` необязателен, добавлено `skip` («не загружать»). Действует самый длинный совпавший путь. В старом проекте карта была общей и без «пропуска» (там `'skip'` кодировался значением `our`) |
| `ImportRun` (новая таблица) + enum `ImportStatus` | журнал запусков импорта: статус, прогресс, счётчики (`summary`), отчёт (`report`), файл фида на диске |
| `Setting` `search.stale` | пометка «поисковый индекс отстаёт от каталога» |

Соответствие старого: `feed_map` → `FeedCategoryMap`, `price_conflict`/`supplier_price` → `Product.priceConflict`/`supplierPrice`
(логика — `docs/CATALOG-IMPORT.md`), `products.locked` (JSON) → `ProductFieldLock` (поля называются как в Prisma: `nameUk`, `price`…),
`products.sub` (одно значение) → дерево `Category` (до 2 уровней подкатегорий под нашей категорией).

## Изменения схемы на Этапе 2 (витрина, шаг 2.6 — заказы), миграция `20260925115302_order_checkout`

Только добавления:

| Что | Зачем |
|---|---|
| `Order.recipientName`, `recipientPhone` | получатель на момент заказа («Прізвище Ім'я», `+380XXXXXXXXX`); `Client.phone` — единый клиент по телефону |
| `Order.deliveryType` | Нова Пошта: `warehouse` (отделение) / `postomat` / `address` (курьер НП); номер отделения или адрес — в `npWarehouseRef` (текстом до подключения справочника НП, Этап 3) |
| `Order.source` | `site` или `one_click` («Купити в 1 клік») |
| `Order.lang` | язык, на котором покупатель оформил заказ (для сообщений) |
| `Order.accessKey` | ключ ссылки страницы «Дякуємо» (`/order/HM-1001?k=…`): без него страница заказа не открывается |
| `DeliveryMethod += PICKUP, TO_CONFIRM` | самовывоз из магазина; «уточнить» (для «в 1 клік») |
| `PayMode += LATER` | «уточнить у менеджера» (для «в 1 клік») |

Используются впервые (были в схеме с Этапа 0): `Order`, `OrderItem` (цена-снимок со скидкой), `OrderHistory`, `Client`, `Outbox` (сообщения менеджерам в Telegram:
`DEV` — режим-заглушка без токена бота), `Warehouse` (склад «Одеса», id `default`), `StockItem.onHand` (наш остаток), `StockMovement` (`ADJUSTMENT` — правка в админке,
`SALE` — списание под заказ, `RETURN` — возврат при отмене). `Setting` `shop.checkout` — настройки оформления (предоплата, способы доставки и оплаты).
Номер заказа `HM-####` = `1000 + Order.seq` (как в старом проекте `HM-(1000+id)`).

## Изменения схемы на Этапе 2 (шаг 2.7 — главная), миграция `20260925132337_product_hit_new`

Только добавления: `Product.isHit` и `Product.isNew` (Boolean, по умолчанию false, с индексами) — отметки «Хіт» и «Новинка», которые ставит владелец в админке.
Импорт фида эти поля не трогает. В старом проекте аналога не было (переносить нечего). Настройки главной — `Setting["shop.home"]` (без изменения схемы).

## Миграция `search_query_stats` (после шага 2.7)

Новая таблица `SearchQueryDay` (день + нормализованный текст запроса, счётчик, сколько нашлось) — для подсказок поиска на главной. Личных данных нет, записи старше 90 дней
удаляются. В старом проекте аналога не было.

## Миграция `photo_style` (фирменный стиль фото)

Только добавления: `ProductImage.styledUrl` (`/media/s<версия>/…`), `styledAt`, `styledError`; `MediaSyncRun.kind` (`download` | `style`).
Включение стиля — `Setting["media.style"] = { on }`. Файлы стиля — в той же папке `MEDIA_DIR` (подпапка `s1`).

## Миграции `banners_admin` и `ads_permission` (реклама и баннеры)

`Banner` была заготовкой с Этапа 0 (место `zone`, тексты, картинки для компьютера/телефона, ссылка, даты, `visible`, показы, нажатия) — дополнена
(только добавления): `name`, `buttonUk/Ru`, `theme`, `sort`, `settings` (JSON: через сколько товаров, какие разделы), `createdBy`, `createdAt/updatedAt`.
Прежний баннер главной (`Setting["shop.home"].banner`) у владельца был пустым и выключенным — переносить нечего; поле больше не используется.
`ads_permission`: право `ads.edit` ролям owner и admin. В старом проекте баннеров не было.

## Миграция `media_local_copies` (свои копии фото)

Только добавления: `ProductImage.localUrl` (адрес своей копии `/media/…`), `localBytes`, `localAt`, `localError`; таблица `MediaSyncRun` (запуски скачивания).
Сами файлы — в папке `MEDIA_DIR` (не в базе): при переезде на сервер папку нужно скопировать (или скачать заново кнопкой). В старом проекте фото были только ссылками на поставщика.

## Миграция `20260925170523_warehouses_pickup_np_refs` (после шага 2.7: магазины и Нова Пошта)

Только добавления:
- `Warehouse`: `cityUk/cityRu`, `addressUk/addressRu`, `schedule` (JSON, график Пн…Нд — `packages/core/src/site/schedule.ts`), `isPickup` (можно забрать заказ здесь), `sort`.
  Данные: основной склад (`isDefault`) стал точкой самовывоза «Одеса», адрес взят из «Контактов». Остатки — как и раньше, `StockItem` по точкам.
- `Order`: `npCityRef`, `npPointRef` — коды города и отделения/почтомата из справочника Новой Почты (для будущей ТТН), `pickupWarehouseId` — из какого магазина самовывоз
  (связь с `Warehouse`, при удалении точки — `NULL`). `npWarehouseRef` по-прежнему хранит то, что видно человеку («Відділення №12: вул. …» или номер/адрес, написанный вручную).
- `Setting["site.contacts"]` получил поле `schedule` (график выбором); `hoursUk/hoursRu` собираются из него автоматически. Старые записи без графика читаются как раньше.

В старом проекте склад был один (`stock` в товаре), точек самовывоза и справочника НП в заказе не было — переносить нечего.

## Миграция `20260926120000_order_messages` (шаг 4.2: сообщения покупателю)

Только добавления: `OutboxState.NO_CHANNEL` (покупатель ещё не подключил бота — текст копируют вручную), `Outbox.audience` (`manager` | `client`,

Шаблоны: в базе владельца уже были 8 шаблонов прототипа — при первом открытии добавились только тексты для новых статусов («Не дозвонились»,

В старом проекте то же самое — таблицы `templates` и `outbox` (сообщения клиенту шли только тем, у кого есть Telegram).
