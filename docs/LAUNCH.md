# Переезд на сервер и запуск (шаг 8.5)

Как перенести магазин с компьютера владельца на арендованный сервер с настоящим доменом — **без потери заказов, клиентов, остатков и ключей** —
и как открыть его для покупателей и Google. Всё по шагам; команды — копировать как есть (что после `#` — пояснение, его не вводить).

Связанные инструкции: как устроен сайт на сервере — `deploy/README.md`; резервные копии — `docs/BACKUPS.md`; проверка после переезда
(тестовые заказы, телефоны, браузеры) — **`docs/LAUNCH-CHECKLIST.md`**.

## Коротко: что будет

1. **Заранее** (любой день, магазин на ПК работает как обычно): купить домен и сервер, подготовить сервер, запустить на нём **пустой** сайт
   и убедиться, что https работает. Можно сделать **репетицию**: перенести копию с ПК, посмотреть — и ничего не потерять (раздел 4).
2. **День переезда** (вечером, когда заказов мало; ~1 час): выключить сайт на ПК → сделать последнюю копию → перенести её на сервер
   одной командой → включить бота и фоновые задачи на сервере → перенастроить сервисы на домен.
3. **Проверка**: пройти `docs/LAUNCH-CHECKLIST.md` (тестовые заказы, оплаты, бот, телефоны).
4. **Открытие для Google** — одна кнопка в админке, когда всё проверено.
5. Если что-то пошло не так — **откат** (раздел 9): данные с сервера возвращаются на ПК той же копией.

Что **переносится**: база (заказы, клиенты, товары, остатки, склад, тексты и настройки сайта, сотрудники, ключи «Интеграций»), фото товаров
и отзывов, ключ шифрования. **Не переносится**: поисковый индекс (собирается на сервере сам), скачанные фиды (не нужны), файл `.env`
(на сервере свой). Данные **старого магазина** (прототип в соседней папке) в новую базу пока не переносились — это отдельный вопрос (Д68).

## 1. Домен и сервер

- **Сервер**: VPS на Linux **Ubuntu 24.04**, 2 ядра, 4 ГБ памяти, от 60 ГБ SSD, Европа или Украина (подробнее — `deploy/README.md`,
  «Требования к серверу»; выбор хостинга — вопрос Д65). После покупки хостинг присылает **адрес сервера** (IP, например `203.0.113.10`)
  и пароль/ключ для входа пользователя `root`. В панели хостинга открыть порты **22, 80, 443** (если там есть фаервол).
- **Домен** (например `handyman.com.ua`; выбирает владелец): в кабинете регистратора домена → «DNS» → добавить запись
  **тип `A`, имя `@`, значение — адрес сервера**. Если нужен и `www` — ещё одну `A`-запись с именем `www` (тогда в `.env` сервера
  `SITE_ADDRESS=handyman.com.ua, www.handyman.com.ua`). Запись начинает работать от нескольких минут до нескольких часов.
  Проверить на ПК: `nslookup handyman.com.ua` в PowerShell — в ответе должен быть адрес сервера.

## 2. Подготовить сервер (заранее)

### 2.1 Войти на сервер с компьютера

В Windows 10/11 программа входа уже есть. **Пуск → PowerShell** и:

```powershell
ssh root@203.0.113.10          # адрес — свой. Первый раз спросит «Are you sure…» — написать yes; затем пароль от хостинга
```

Дальше все команды разделов 2–8 — в этом окне (это уже терминал сервера). Выйти — `exit`.

### 2.2 Docker и папка проекта

```bash
curl -fsSL https://get.docker.com | sh              # Docker (официальный способ), 1–2 минуты
mkdir -p /opt/handyman
```

### 2.3 Доступ сервера к коду на GitHub (ключ «только чтение»)

Репозиторий приватный. Сервер получает **свой ключ только для чтения этого репозитория** (deploy key) — не ваш пароль и не ваш аккаунт (Д67).

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/handyman_deploy -C "handyman-server"
cat ~/.ssh/handyman_deploy.pub                        # показать открытую часть ключа — одна строка «ssh-ed25519 AAAA… handyman-server»
```

На GitHub (в браузере, под своим аккаунтом): репозиторий **handyman → Settings → Deploy keys → Add deploy key** → Title `server`,
в поле Key вставить строку из команды выше, галочку «Allow write access» **не ставить** → Add key. Затем на сервере:

```bash
cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/handyman_deploy
  IdentitiesOnly yes
EOF
git clone git@github.com:cynepxep/handyman.git /opt/handyman     # первый раз спросит «Are you sure…» — yes
cd /opt/handyman
```

### 2.4 Настройки сервера (`.env`)

```bash
cp .env.production.example .env
openssl rand -hex 24        # запустить 4 раза: каждая строка — новый пароль (для базы, поиска, ADMIN_TOKEN, HEALTH_KEY)
nano .env                   # редактор: стрелки — перемещение, Ctrl+O → Enter — сохранить, Ctrl+X — выйти
chmod 600 .env
```

Что вписать в `.env` (остальное можно не трогать):

| Строка | Что вписать |
|---|---|
| `SITE_ADDRESS` | домен без `https://` (например `handyman.com.ua`) |
| `PUBLIC_URL` | тот же домен с `https://` (`https://handyman.com.ua`) |
| `POSTGRES_PASSWORD`, `MEILI_MASTER_KEY`, `ADMIN_TOKEN`, `HEALTH_KEY` | по одному паролю из `openssl rand -hex 24` |
| `SECRETS_KEY` | **оставить пустым** — при переносе скрипт сам впишет ключ шифрования с ПК (раздел 5) |
| `HM_WORKER=off` | **добавить эту строку** на время подготовки: пока сайт на ПК работает, сайт на сервере не читает бота и не шлёт сводки и напоминания (иначе после репетиции менеджеры получали бы всё дважды). Убирается в день переезда |
| `BOT_TOKEN`, ключи сервисов | **пусто**: ключи из «Интеграций» переедут вместе с базой. Если на ПК какой-то ключ был записан в `.env` (в «Интеграциях» у поля подпись «из файла .env»), — перепишите его сюда в день переезда |

Пароли из `.env` сохраните в менеджере паролей (или распечатайте и уберите). **Никому не присылайте** — ни в мессенджеры, ни Claude.

### 2.5 Первый запуск (пустой сайт)

```bash
docker compose -f docker-compose.prod.yml up -d --build      # первая сборка — 5–10 минут
docker compose -f docker-compose.prod.yml ps                 # все четыре — «Up», у web/postgres/meilisearch — «healthy»
curl http://127.0.0.1:3000/api/health                        # {"status":"ok"}
```

Затем в браузере на ПК открыть `https://<домен>` — должна открыться пустая витрина **с замком** (https). Не открывается — `deploy/README.md`,
«Если что-то не так» (чаще всего запись DNS ещё не заработала или закрыты порты 80/443). **`hm seed` не запускать** — база придёт с ПК.

## 3. Проверить копирование файлов с ПК на сервер

В Windows есть программа `scp` (копирование по тому же входу, что `ssh`). Проверка — **на ПК**, в новом окне PowerShell:

```powershell
ssh root@203.0.113.10 "mkdir -p /root/transfer"
```

Если спросило пароль и без ошибок вернулось — всё готово. (Кому удобнее мышкой — программа **WinSCP**: вход по тому же адресу и паролю,
перетаскивание папок в `/root/transfer`.)

**Лучше сразу — вход по ключу, без пароля** (опыт переезда 2026-10-05: пароль при вводе не виден, а копирование команды подменяет пароль
в буфере обмена — вставлялась команда, и сервер отвечал `Permission denied`). На ПК, в PowerShell:

```powershell
ssh-keygen -t ed25519                     # на все вопросы — Enter; «Overwrite?» — n (ключ уже есть)
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@203.0.113.10 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
#   ↑ спросит пароль последний раз: СНАЧАЛА вставить команду и нажать Enter, ПОТОМ скопировать пароль в панели хостинга и вставить
ssh root@203.0.113.10 "echo OK"           # пароль больше не спрашивает
```

Дальше все команды для сервера можно давать прямо с ПК одной строкой: `ssh root@<адрес> "cd /opt/handyman && …"` (`-t` — если команда что-то спрашивает).

## 4. Репетиция (по желанию, рекомендуется)

Всё как в дне переезда (раздел 5), но **сайт на ПК не выключать** и на сервере **оставить `HM_WORKER=off`**. Так видно заранее, сколько
длится перенос фото и всё ли открывается на сервере. Заказы, пришедшие на ПК после репетиции, в день переезда перенесутся заново — последняя
копия заменяет на сервере всё целиком.

## 5. День переезда

### 5.1 На ПК: последняя копия

1. Нажать **«Обновить сайт»** (на ПК и сервере должна быть одна версия; дождаться, пока откроется админка).
2. Предупредить менеджеров: на ~1 час заказы с сайта не приходят.
3. **Закрыть окно «Сайт Handyman — не закрывайте это окно»** — сайт на ПК остановлен, новых заказов на нём больше не будет.
   Старый магазин (прототип), если он работает на **том же боте**, — тоже остановить (два сайта на одном боте мешают друг другу: ошибка 409).
4. Docker Desktop должен оставаться запущенным (зелёный значок). Открыть PowerShell **в папке проекта** (Проводник → папка проекта →
   в адресной строке набрать `powershell` → Enter) и сделать копию:

   ```powershell
   pnpm backup:now
   ```

   В конце — `Готово: 2026-10-05_193000-manual …` — **запомнить имя копии**.
   «Уже идёт копирование или проверка» — сайт после «Обновить сайт» начал свою ежедневную копию, а окно закрыли посреди неё; отметка
   снимается сама через 3 часа, сразу — так (затем снова `pnpm backup:now`):

   ```powershell
   'DELETE FROM "Setting" WHERE key = ''backup.lock'';' | & "C:\Users\Дима\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe" exec -i handyman-next-postgres-1 psql -U handyman -d handyman
   ```
5. Отправить копию и фото на сервер (из той же папки проекта; адрес и имя копии — свои). Папка копий по умолчанию — `.data\backups`;
   если в `.env` на ПК задан `BACKUP_DIR` — она там (путь виден в админке «Резервные копии»):

   ```powershell
   scp -r .data\backups\2026-10-05_193000-manual root@203.0.113.10:/root/transfer/
   scp -r .data\backups\media root@203.0.113.10:/root/transfer/
   ```

   Фото может быть несколько гигабайт — это минуты или десятки минут. Если связь оборвалась — повторить ту же команду.

### 5.2 На сервере: перенос одной командой

```bash
cd /opt/handyman
git pull                                                          # та же версия, что на ПК
docker compose -f docker-compose.prod.yml up -d --build           # если была новая версия — пересобрать
bash deploy/move-from-pc.sh /root/transfer/2026-10-05_193000-manual
```

Скрипт показывает, что сделает, и спрашивает — написать `да` и Enter. Он: проверяет копию → вписывает в `.env` **ключ шифрования с ПК**
(если там уже другой — остановится и объяснит) → кладёт копию и фото в хранилище копий сервера → останавливает сайт → восстанавливает базу
(перед этим — копия того, что было на сервере) → запускает сайт → ждёт ответа → пересобирает поиск. В конце — **«ГОТОВО»**. Журнал — файл
`move-last.log` в `/opt/handyman` (если «НЕ ПОЛУЧИЛОСЬ» — покажите его Claude).

### 5.3 Включить бота и фоновые задачи на сервере

```bash
nano .env              # удалить строку HM_WORKER=off (и вписать ключи, которые на ПК были в .env, если такие есть)
docker compose -f docker-compose.prod.yml up -d
```

С этого момента на сервере работают бот (читает сообщения сам — ничего настраивать в Telegram не нужно), сводки в 21:00, напоминания,
тревоги и **ночные копии**.

**Ключи, которые на ПК были в `.env`, на сервер не переезжают** (опыт 2026-10-05: токен бота, чат менеджеров, ключ Новой Пошты). В «Интеграциях»
на сервере у таких сервисов — «не задано»/«заглушка»: открыть на ПК файл `.env` Блокнотом и вписать значения в «Интеграции» (хранятся в базе
зашифрованными), «Сохранить» → «Проверить подключение».

Затем — **автообновление** (`deploy/README.md`): сервер сам ставит новые версии из `main`, владельцу больше ничего запускать не нужно:

```bash
bash deploy/install-auto-update.sh
```

### 5.4 На ПК: больше не запускать сайт

Сайт на ПК теперь не должен запускаться: он читал бы того же бота и слал бы менеджерам те же сводки. В PowerShell в папке проекта:

```powershell
Set-Content .data\moved-to-server.txt "Магазин работает на сервере с $(Get-Date -Format yyyy-MM-dd)"
```

После этого ярлык **«Обновить сайт»** на ПК не запускает сайт, а пишет, что магазин переехал (обновление теперь — на сервере:
`bash deploy/update.sh`). Вернуть сайт на ПК — раздел 9.

## 6. Проверка после переноса

1. `https://<домен>/admin` → войти **своим логином и паролем с ПК** (база перенесена; с кодом из приложения, если включён).
2. **Заказы, Клиенты, Товары** — те же, что были на ПК; последний заказ на месте. **Поиск** на витрине находит товары. Фото видны.
3. **«Интеграции»** — у каждого подключённого сервиса **«Проверить подключение»** — всё зелёное (если у поля красное «не читается (сменился ключ шифрования)» —
   ключ шифрования не тот: `SECRETS_KEY` в `.env` сервера должен совпадать с ПК).
4. **«Резервные копии» → «Сделать копию сейчас»**, затем **«Проверить восстановление»** — обе зелёные. Подключить облако (Д59), если ещё нет.
5. **«Проверка перед запуском»** — все пункты «готово» (кроме «Сайт открыт для Google» — его откроем в конце). Там же видно, что
   `SECRETS_KEY`, пароли базы и поиска, `PUBLIC_URL` на сервере свои.
6. **«Ошибки»** — нет новых.

## 7. Перенастроить внешние сервисы на домен

| Сервис | Что сделать |
|---|---|
| **Telegram-бот** | Ничего: сервер читает бота сам. Проверить — написать боту `/start`: должна появиться кнопка **«Магазин»** (она ведёт на `PUBLIC_URL`) |
| **Mini App** (кнопка слева от поля ввода в боте) | В Telegram: **@BotFather → /mybots → ваш бот → Bot Settings → Menu Button** → прислать адрес `https://<домен>` → название кнопки, например «Магазин». Открыть бота на телефоне → кнопка → сайт открывается внутри Telegram |
| **KeyCRM** | «Интеграции → KeyCRM» → блок «Адрес для KeyCRM» → **«Копировать»** (адрес уже с доменом). В KeyCRM: автоматизация «Замовлення → Зміна статусу» → «Відправити вебхук», POST, вставить адрес. Смена статуса в KeyCRM → меняется и на сайте сразу (раньше — раз в 10 минут опросом). **Передачу заказов в KeyCRM** включать, только когда старый магазин больше не шлёт туда заказы (иначе дубли, Д54) |
| **monobank** | Ничего: адрес для уведомлений об оплате берётся из `PUBLIC_URL`. «Проверить подключение» + один платёж 1–10 ₴ по `docs/LAUNCH-CHECKLIST.md` |
| **Checkbox**, **Нова Пошта**, **SMS** | Ничего, только «Проверить подключение» |
| **Старый магазин (прототип)** | Не запускать на том же боте (ошибка 409 — сообщения читает то одна, то другая программа). Адреса старого магазина, если он был открыт в интернете, — решить отдельно (Д69) |

## 8. Сторож (UptimeRobot) и открытие

**Сторож** проверяет каждые 5 минут, что сайт открывается, и пишет владельцу, если нет (Д62):

1. Зарегистрироваться на **uptimerobot.com** (бесплатный тариф).
2. **+ New monitor** → тип **HTTP(s)** → Friendly name `Handyman` → URL **`https://<домен>/api/health`** → интервал 5 минут.
3. «Alert contacts» — своя почта (и Telegram, если он есть в вашем тарифе) → **Create monitor**. Через минуту статус — «Up».

Сайт отвечает `{"status":"ok"}` (или `503 error`, если не работает база, поиск или кончается диск) — других подробностей наружу нет;
подробности — в админке («Здоровье сайта» на главной).

Затем:

1. Пройти **`docs/LAUNCH-CHECKLIST.md`** целиком (тестовые заказы, оплаты, бот, телефоны и браузеры).
2. **Подтвердить сайт в Google Search Console** (бесплатный сервис Google: сколько страниц в поиске, по каким запросам находят, ошибки) —
   по шагам в «Настройки → Проверка перед запуском» → раздел **«Google Search Console и карта сайта»**: на `search.google.com/search-console`
   «Добавить ресурс» → «Префикс URL» → `https://<домен>` → способ «Тег HTML» → скопировать тег → вставить в поле на этой странице →
   «Сохранить» (тег сразу появляется на главной) → в Search Console «Подтвердить» → в админке отметка «Подтверждено» → «Сохранить».
   Пробуйте до кнопки «Открыть»; если Google ответит, что не смог проверить сайт, — повторите «Подтвердить» после шага 3 (допущение: не проверено вживую).
3. **Открыть для Google**: там же внизу **«Открытие сайта для Google»** → галочка «Понимаю…» →
   **«Открыть сайт для Google»**. После этого поисковикам видны главная, каталог, разделы, товары и страницы; админка, корзина,
   оформление, поиск, «Обране», сравнение и адреса с фильтрами закрыты (файл `https://<домен>/robots.txt`, в нём же строка `Sitemap:`).
   Закрыть обратно — той же кнопкой.
4. **Отправить карту сайта**: в Search Console → «Файлы Sitemap» → вписать `sitemap.xml` → «Отправить». Карта (`https://<домен>/sitemap.xml`)
   собирается сама: главная, каталог, разделы и задачи с товарами, страницы, все товары — на обоих языках. Пока сайт закрыт, по этому
   адресу «нет страницы» (видят только вошедшие в админку). Через 1–3 дня — раздел «Страницы» в Search Console: сколько попало в поиск.

## 9. Откат

### Не так после обновления сайта

`bash deploy/update.sh` сам возвращает прежнюю версию, если новая не запустилась. Если новая запустилась, но в данных что-то не так —
восстановить копию «перед обновлением» (`deploy/README.md`, «Восстановление копии на сервере»; копии — в «Резервных копиях»).

### Вернуть магазин на ПК (сервер не подходит или сломан)

Сайт на ПК виден только на этом компьютере (не по домену): на время отката заказы принимают по телефону, в боте и в KeyCRM —
как договоритесь (Д69). Данные при этом не теряются.

**Сервер работает** — забрать свежую копию с сервера:

```bash
cd /opt/handyman
bash deploy/export-for-pc.sh                                  # копия сейчас → папка /root/handyman-export (фото тоже; без фото: --no-media)
docker compose -f docker-compose.prod.yml stop web            # остановить сайт на сервере (бот и сводки — больше не с сервера)
```

На ПК (PowerShell в папке проекта; имя копии — из ответа команды выше):

```powershell
scp -r root@203.0.113.10:/root/handyman-export/2026-10-07_101500-manual .data\backups\
scp -r root@203.0.113.10:/root/handyman-export/media .data\backups\
Remove-Item .data\moved-to-server.txt
pnpm backup:restore 2026-10-07_101500-manual --yes
```

Затем ярлык **«Обновить сайт»** — сайт на ПК запустится с данными сервера. На сервере выгрузку удалить: `rm -rf /root/handyman-export`
(в ней ключ шифрования). Если на ПК `BACKUP_DIR` свой — класть в неё, а не в `.data\backups`.

**Сервер недоступен совсем** — взять последнюю копию из облака (Д59; `docs/BACKUPS.md`, «С другого компьютера / из облака»), положить её
и папку `media` в `.data\backups` на ПК, дальше — те же команды `Remove-Item …` и `pnpm backup:restore …`. Без облака — только копия,
которую вы скачивали сами («Резервные копии → Скачать»): заказы после неё придётся восстановить вручную по KeyCRM и сообщениям бота.

**Бот**: после отката его читает сайт на ПК. Кнопка Mini App в BotFather ведёт на домен — пока сервер не работает, она не откроется
(можно временно убрать: @BotFather → Menu Button → «Remove»).

## Если что-то не так

| Признак | Что делать |
|---|---|
| `move-from-pc.sh`: «SECRETS_KEY в .env не совпадает…» | в `.env` сервера оставить `SECRETS_KEY=` пустым и запустить снова — скрипт впишет ключ с ПК |
| `move-from-pc.sh`: «это не папка резервной копии» | в `/root/transfer` должна быть папка вида `2026-10-05_193000-manual` с файлами `db.dump`, `manifest.json`, `secrets.key`; не переименовывать |
| «Интеграции»: «не читается (сменился ключ шифрования)» | ключ шифрования не тот: сравнить `SECRETS_KEY` в `.env` сервера с файлом `.data\secrets.key` (или `SECRETS_KEY` в `.env`) на ПК, исправить, `docker compose -f docker-compose.prod.yml up -d` |
| фото на сервере не видны | папка `media` не перенеслась: повторить `scp -r .data\backups\media …` и `bash deploy/move-from-pc.sh …` (или «Фото товаров → Проверить файлы на диске» — сайт докачает фото поставщиков сам) |
| бот не отвечает, в «Ошибках» — «бота уже читает другая программа» | где-то ещё запущен сайт на ПК или старый прототип с тем же ботом — выключить |
| менеджеры получают сводки дважды | сайт на ПК запущен — закрыть его окно и создать `.data\moved-to-server.txt` (раздел 5.4) |
| после переноса витрина пустая (каталог без разделов), а заказы в админке есть | сайт показывает закэшированное с пустой базы: `docker compose -f docker-compose.prod.yml up -d --force-recreate web` (с 2026-10-05 `move-from-pc.sh` делает это сам) |
| бот молчит, в журнале сайта нет строк `[bot]` | токена бота нет на сервере (на ПК был в `.env`): вписать в «Интеграции → Telegram-бот» |
| сайт не открывается по домену, а `curl http://127.0.0.1:3000/api/health` — ok | `docker compose -f docker-compose.prod.yml logs caddy`: DNS «A» не на этот сервер или закрыты порты 80/443 |
