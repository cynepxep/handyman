# Сайт на сервере (шаг 8.4): сборка в Docker и обновление

Коротко: на сервере сайт работает в **Docker** — четыре «контейнера» (изолированные программы), которые запускаются одной командой:

| Контейнер | Что это | Наружу |
|---|---|---|
| `web` | сам сайт: витрина, админка, Mini App, API, фоновые задачи (сводки, копии, тревоги) и бот | нет (только для самого сервера: `127.0.0.1:3000`) |
| `postgres` | база данных (PostgreSQL 16) | нет |
| `meilisearch` | поиск по товарам | нет |
| `caddy` | «входная дверь»: сам получает и продлевает **https-сертификат** для домена, передаёт запросы сайту | порты 80 и 443 |

Отдельный бот (`apps/bot`) и Redis на сервере **не нужны**: бот и фоновые задачи работают внутри сайта, лимиты форм — в базе.

Полный переезд с ПК на сервер (перенос базы, фото, ключа, настройка бота и оплат на домен), откат и открытие для Google — **`docs/LAUNCH.md`**,
проверка перед открытием — `docs/LAUNCH-CHECKLIST.md` (шаг 8.5).
Здесь — как устроена сборка, первый запуск на пустом сервере и обновление.

## Файлы

| Файл | Что делает |
|---|---|
| `apps/web/Dockerfile` | образ сайта: сборка Next.js «standalone» (самодостаточная папка) на Ubuntu 24.04, клиент PostgreSQL 16 для копий, запуск не от root |
| `docker-compose.prod.yml` | все четыре контейнера, тома с данными, ограничение размера журналов |
| `deploy/Caddyfile` | https для домена, загрузка фида до 70 МБ, настоящий адрес покупателя для лимитов (`X-Forwarded-For`) |
| `deploy/entrypoint.sh` | запуск сайта: обновить базу (миграции + ремонты) → собрать поиск, если его нет → запустить |
| `deploy/hm` | служебные команды внутри контейнера (ниже) |
| `deploy/update.sh` | обновление одной командой с копией и откатом |
| `deploy/move-from-pc.sh` | переезд: копия с ПК → ключ шифрования в `.env` → восстановление → поиск (одной командой, `docs/LAUNCH.md`) |
| `deploy/export-for-pc.sh` | свежая копия с сервера в обычную папку — скачать на ПК (откат, `docs/LAUNCH.md`) |
| `.env.production.example` | шаблон настроек сервера (пароли, домен, ключи) |

## Данные — в томах Docker

Контейнер можно удалить и собрать заново — данные остаются в **томах** (`docker volume ls`, имена начинаются с `handyman-prod_`):

| Том | Что внутри | В копии (8.1)? |
|---|---|---|
| `postgres_data` | база | да (`db.dump`) |
| `media` | фото товаров и отзывов (`MEDIA_DIR=/media`) | да (папка `media` в копиях) |
| `web_data` | ключ шифрования `secrets.key` (если `SECRETS_KEY` не задан), скачанные фиды | ключ — да |
| `backups` | резервные копии (`BACKUP_DIR=/backups`) | — (вторая копия — в облаке, «Интеграции → Резервные копии») |
| `meili_data` | поисковый индекс | нет — пересобирается `hm reindex` |
| `caddy_data` | https-сертификаты | нет — Caddy получит заново |

**Не удалять тома** (`docker compose down -v`, `docker volume rm …`) — это удаление базы и фото.

## Требования к серверу

- **Linux Ubuntu 24.04** (другой Linux с Docker тоже подойдёт, но инструкции — для Ubuntu).
- **2 ядра, 4 ГБ памяти, от 60 ГБ SSD** (фото и копии растут; каталог ~9 000 товаров с фото ≈ несколько ГБ, копии — ещё столько же).
  Сборка образа занимает 2–3 ГБ памяти на пару минут: при 2 ГБ памяти включите файл подкачки.
- Расположение — Европа или Украина (быстрее для покупателей). Цены и тарифы — уточнить у хостинга (вопрос Д65 в `docs/QUESTIONS-TO-OWNER.md`).
- Домен, у которого запись **DNS «A»** указывает на адрес сервера (до первого запуска — иначе Caddy не получит сертификат).
- Открыты порты **80 и 443** (в панели хостинга / фаерволе). Порты базы и поиска открывать **не нужно**.

## Первый запуск на пустом сервере

Команды — в терминале сервера (SSH). Всё, что после `#`, — пояснение, его не вводить.

```bash
# 1. Docker (официальный способ для Ubuntu)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # затем выйти из SSH и зайти снова

# 2. Проект (репозиторий приватный: сначала ключ «только чтение» для GitHub — docs/LAUNCH.md, раздел 2.3; тогда адрес git@github.com:cynepxep/handyman.git)
sudo mkdir -p /opt/handyman && sudo chown $USER /opt/handyman
git clone https://github.com/cynepxep/handyman.git /opt/handyman
cd /opt/handyman

# 3. Настройки: шаблон → .env, вписать домен и пароли (каждый пароль: openssl rand -hex 32)
cp .env.production.example .env
nano .env
chmod 600 .env

# 4. Собрать и запустить (первая сборка — 5–10 минут)
docker compose -f docker-compose.prod.yml up -d --build

# 5. ТОЛЬКО на пустой базе (новый магазин без переноса с ПК): роли, права, учётная запись owner (пароль — ADMIN_TOKEN из .env)
docker compose -f docker-compose.prod.yml exec web hm seed

# 6. Проверка
docker compose -f docker-compose.prod.yml ps                       # все четыре — «Up», у web/postgres/meilisearch — «healthy»
curl http://127.0.0.1:3000/api/health                              # {"status":"ok"}
```

Затем открыть `https://<домен>/admin`, войти как `owner`, сменить пароль и включить код из приложения («Мой аккаунт»),
открыть **«Проверка перед запуском»** — все пункты должны стать «готово».

При **переезде с ПК** шаг 5 не нужен: база восстанавливается из копии командой `bash deploy/move-from-pc.sh <копия>` (порядок — `docs/LAUNCH.md`).

## Обновление

```bash
cd /opt/handyman
bash deploy/update.sh
```

Что происходит: резервная копия → `git pull` → сборка нового образа (сайт в это время работает) → перезапуск (база обновляется сама:
миграции и готовые ремонты из `packages/db/prisma/repairs/`) → ожидание ответа `/api/health` (до 5 минут) → пересборка поиска.
Если новая версия не ответила — **сам возвращает прежний образ**, и сайт работает как до обновления; в `update-last.log` — причина.
Простой сайта при удачном обновлении — несколько секунд (Caddy в это время ждёт сайт, а не показывает ошибку).

## Служебные команды (`hm`)

```bash
docker compose -f docker-compose.prod.yml exec web hm <команда>       # сайт работает
docker compose -f docker-compose.prod.yml run --rm web <команда>      # сайт остановлен
```

| Команда | Что делает |
|---|---|
| `hm help` | список команд |
| `hm migrate` | обновить базу (делается само при каждом запуске сайта) |
| `hm seed` | **один раз на пустой базе**: роли, права, owner. Повторно не запускать — перезаписывает права ролей |
| `hm reindex` | пересобрать поиск из базы |
| `hm backup-now` | копия сейчас (как кнопка в «Резервных копиях») |
| `hm backup-check [копия]` | проверить восстановление во временную базу (рабочую не трогает) |
| `hm backup-restore <копия> --yes` | **восстановить** копию в рабочую базу — только при остановленном сайте (ниже) |

Восстановление копии на сервере:

```bash
C="docker compose -f docker-compose.prod.yml"
$C stop web
$C run --rm web backup-restore 2026-09-28_033000-auto --yes   # имя копии — из «Резервных копий» или: $C run --rm web ls /backups
$C up -d web                                                  # база обновится до текущей версии сама
$C exec web hm reindex                                        # поиск — по восстановленным товарам
```

Копия с ПК переносится одной командой — `bash deploy/move-from-pc.sh <папка копии>` (кладёт копию и фото в том, вписывает ключ шифрования,
восстанавливает, пересобирает поиск; `docs/LAUNCH.md`). Вручную: `docker compose -f docker-compose.prod.yml cp ./2026-09-28_120000-manual web:/backups/`.

## Полезное

```bash
C="docker compose -f docker-compose.prod.yml"
$C logs --tail 200 web          # журнал сайта (ошибки — ещё и в админке «Ошибки»)
$C logs --tail 100 caddy        # журнал https (сертификат не получен → проверить DNS «A» и порты 80/443)
$C restart web                  # перезапустить сайт
$C down                         # остановить всё (данные в томах остаются)
docker system df                # сколько места занимает Docker
```

## Проверка без сервера (на своём компьютере)

В `.env` — `SITE_ADDRESS=localhost` и `PUBLIC_URL=https://localhost`: Caddy выдаст внутренний сертификат (браузер предупредит о нём —
это нормально для проверки). Сайт — `https://localhost`, тесты в браузере: `E2E_BASE_URL=https://localhost pnpm test:e2e`.

## Если что-то не так

| Признак | Что делать |
|---|---|
| сборка остановилась на шрифтах (`fonts.gstatic.com`, `next/font`) | сеть на миг пропала — запустить `update.sh` ещё раз |
| `web` перезапускается по кругу | `$C logs --tail 200 web`: чаще всего неверный пароль базы в `.env` (`POSTGRES_PASSWORD` меняли после первого запуска) |
| сайт не открывается по домену, `curl http://127.0.0.1:3000/api/health` — ok | `$C logs caddy`: DNS «A» не на этот сервер или закрыты порты 80/443 |
| «Проверка перед запуском» ругается на пароли/ключи | вписать свои значения в `.env`, затем `$C up -d` |
